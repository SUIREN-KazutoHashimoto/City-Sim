# City-Sim 基本設計書

## 1. 文書情報

- 対象: 現行実装（文書同期時点 `v0.1.83`）
- 更新基準日: 2026-08-26
- **現行ソースコードを正とする。**
- 実効値は `現行仕様書.md`、runtime patch/定数は `詳細設計書.md` を参照する。

## 2. システム概要

City-SimはTypeScript / three.js / Viteで構成するブラウザ向けリアルタイム都市シミュレーションである。

同一simulation time上で次を相互作用させる。

- 都市計画、道路、Block/Parcel、建物、POI
- 公園、森林、駅周辺clearance
- 農場、工場、物流、fleet depot
- 市民、勤務、食事、買物、娯楽
- 徒歩、自家用車、バス、タクシー
- 道路信号、歩行者信号、多車線交通
- 在来鉄道、鉄道旅客、駅、車両基地
- 外部接続高速鉄道と来訪者
- 昼夜環境、Inspector、Performance/UI

## 3. 設計原則

### 3.1 コード優先

設計書は実装の上位契約ではない。コードと文書が食い違った場合、最終import後の実効動作を確認して文書を更新する。

Prototype Patchを使う分野では、base classだけを読んで仕様を確定しない。

### 3.2 データ指向

大量Agent/VehicleはSoA TypedArrayで保持する。Cross-Origin Isolationが使える場合はSharedArrayBufferを利用する。

### 3.3 Coordinator / Store / System / Renderer

- Store: 大量状態を保持
- System: Storeを走査して局所ロジックを更新
- World: 行動、POI、移動手段、複数System間の状態遷移を統合
- Renderer: simulation stateをthree.jsへ同期

RailRendererは現状、operation stateとrender stateの両方を持つため完全分離ではない。

### 3.4 Simulation / Rendering分離

Simulation stepと描画frameを分離する。render-time補間はsimulation判定を置換しない。

道路右左折も「論理Edge/lane」と「表示曲線」を分離し、見た目を直すために信号/IDM/path規則を壊さない。

### 3.5 Runtime tuning chain

`src/version.ts` は版番号だけでなくruntime tuning import入口でもある。

同じprototype methodを複数moduleがwrapするため、**import順は仕様の一部**として扱う。

## 4. 全体構成

```text
main.ts
  ├─ Config / Boot / PreRoll
  ├─ World
  │   ├─ AgentStore / Need / Utility
  │   ├─ CityGenerator / CityPlanning
  │   ├─ Traffic / Signal
  │   ├─ Bus / Taxi / Logistics
  │   ├─ Worker Pools
  │   └─ Rail Passenger Integration

  ├─ External High Speed Rail

  └─ generation / traffic / world / rendering tuning chain
```

## 5. ソース領域の責務

### `src/core`

SimulationClock、SpatialHash、math等。

### `src/config`

JSON設定、値域検証、Seed解決。

### `src/generation`

都市計画、道路/Block/Parcel/建物、特殊施設、公園、鉄道計画、農場/郊外産業、fleet depot、最終land-use refinement。

### `src/agents`

AgentStore、Need、Utility AI。

### `src/traffic`

Road/Sidewalk network、A*、VehicleStore、Traffic、Signal、Bus、Taxi、Logistics、多車線/右左折tuning。

### `src/world`

Agent action lifecycle、POI reserve/release、徒歩/車/バス/タクシー/鉄道の遷移、職場生産効率、外部来訪者、鉄道旅客sidecar。

### `src/rendering`

都市3D、RailRenderer、駅/列車拡張、外部高速鉄道、Inspector、Dashboard、Performance、農地/森林/道路標示、filter/window管理。

## 6. 都市生成設計

### 6.1 Base generation

CityPlanning → RoadNetwork → Block/Parcel → Building/POI → Special Facility/Parkを基礎とする。

### 6.2 後段refinement

現行は複数のruntime tuningを積み重ねる。

代表:

```text
UrbanFootprintBaseline
CityDiversityTuning
ParkPriorityTuning
UrbanFootprintGuard
RuralIndustryAndDepotTuning
AgriculturalEstateTuning
AgriculturalEstateIndexGuard
CityGenerationRefinement
```

後段ほど最終仕様へ近い。

### 6.3 道路密度/車線

中心部では多車線・高道路密度、郊外/低密度ではLocal道路を減らす。

Public roadの最終構造は農地や都市多様化patchの影響を受ける。

### 6.4 公園

初期Park districtと最終公園数を分ける。最終段で高さ帯別の上限へtrimすることで、Park計画値が市街地全体へ過剰拡散するのを防ぐ。

### 6.5 駅周辺

線路物理包絡clearanceと、駅中心からの最終no-building clearanceを別責務にする。

後付けされたfarm/factory/depotも最終検査対象とする。

## 7. 農場・産業設計

### 7.1 Farm estate

Farmを「建物1棟」ではなくland-useとして扱う。

- field
- office
- warehouse
- access road side

を1セットとする。

Field描画範囲とtruck loading位置を分離し、畑の中心へtruckが向かわないようにする。

### 7.2 生産

Production base rateとstaffing efficiencyを分離する。

```text
物理設備/面積 → base process rate
出勤/定員     → efficiency
base × efficiency → actual output
```

Farmはfield areaがbase process rateを決定する。

### 7.3 Supply chain

段階在庫を持ち、truckが実際にsite間を走る。

```text
stage 0 source
→ processor
→ assembler
→ retail / export
```

Money economyとは分離した物理物流modelである。

## 8. 職場設計

Workplaceでは次を別概念として扱う。

- assigned workers（在籍）
- present workers（出勤）
- Work POI capacity（定員）

Inspectorはこの3値を表示する。

Production siteだけはpresent/capacityをactual productionへ適用する。一般office/commercialの効率は現時点でinformational。

## 9. 道路交通設計

### 9.1 論理走行

TrafficSystemのEdge/path/segTを正とし、IDM、信号、歩行者blockを維持する。

### 9.2 Lane runtime

MultiLaneTrafficTuningがlane/target lane/lane changeをsidecar的に追加する。

右左折laneと下流lane reductionは別の問題として扱い、turn時の矛盾をTurningLaneTransitionFixで解消する。

### 9.3 表示軌道

TurningVisualPathTuningは交差点内だけlane center間を曲線補間する。RoadNetworkの実Edgeやlane countを表示都合で変更しない。

## 10. 歩行者設計

SidewalkNetwork上のrouteを保持する。

Crossing safetyでは:

- 横断中歩行者が車両をblock
- 赤信号はroute変更理由にしない
- curb付近でsignal待ち
- 青+安全になったら同routeを継続

とする。

## 11. バス設計

Base BusSystemのstop/runtimeを再利用し、route topologyだけShortBusRouteTuningで再構成する。

設計目標:

- total cyclic route <= 5 km
- old long lineを最低4分割
- 3～4 buses / route
- station feederも同一距離制約

短距離高密度にすることで、長距離路線の重複増便ではなくlocal network化する。

## 12. タクシー設計

TaxiSystemはbase AgentStoreへ大量の専用fieldを追加せず、taxi/passenger mappingをside dataで持つ。

TaxiはRoad Trafficへ参加し、pickup/boarding/occupied/alightingを明示する。

既存AgentStateとの互換のため、waiting/onboard presentationは一部bus stateを再利用する。

## 13. Fleet depot設計

Taxi/Bus/Freightは各専用depotを持つ。

Depot parkingは一般住民へ公開しない。

Vehicle spawn/return位置を実空間へ持たせることで、fleetが都市中へ突然出現する挙動を避ける。

## 14. 鉄道設計

### 14.1 計画座標と走行線形

- planned station: TOD
- physical station/access metadata
- roadNode
- running `line.path`

を区別する。

### 14.2 郊外駅間隔

固定間隔ではなく、base spacingへlocality factorを掛ける。都市外縁ほど駅間を広げる。

### 14.3 運行

RailRendererは現状以下を所有する。

- smooth lines
- train runs
- block occupancy/reservation
- timetable
- signal/turnout state
- terminal/depot state

列車編成は単一 `run.distance` を位置基準とする。

### 14.4 旅客

駅へteleportせず、station accessとplatform waitingを通じて実列車へ乗降する。

## 15. 描画設計

### 15.1 Instancing / LOD

反復geometryはInstancedMeshを基本とし、建物/Agent/Vehicleは距離LODを持つ。

### 15.2 静的物の最終衝突除外

TreeRoadClearanceTuningのように、生成時metadataだけではなく最終RoadNetworkを使ってrender candidateを除外する場合がある。

### 15.3 Filter

Render filterはsimulation停止ではなく描画/sync削減機能。

## 16. Inspector/UI設計

UniversalInspectorをbaseとして、feature-specific tuningが説明文へ追加情報を挿入する。

Workplace、Taxi、Visitor、MultiLane等はこの方式。

UI window shellがdrag/resize/z-order/persistenceを担当する。

## 17. Performance設計

- SharedArrayBuffer / Worker
- SoA
- dirty/active list
- spatial index
- A* route cache
- GPU instancing
- LOD
- rail frame budget
- simulation/render個別計測

## 18. 重要な不変条件

1. ソースコードと最終runtime overrideを仕様の正とする。
2. `src/version.ts` のimport順を変更する場合はpatch chainを再監査する。
3. 道路の表示補正で論理RoadEdge metadataを恒久変更しない。
4. Pedestrian signal待ちでwalk routeを破棄しない。
5. Farm logistics sourceはwarehouse側、field extentは別座標とする。
6. Farm actual productionはfield-based base rate × attendance efficiency。
7. 駅周辺final clearanceは後付け施設も対象とする。
8. 列車編成位置は単一running distanceを基準とする。
9. Station platform/accessはrunning railと無関係な別軌跡へ分離しない。
10. Render filterはsimulation stateを変更しない。

## 19. 技術的負債
