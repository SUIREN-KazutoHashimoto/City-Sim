# City-Sim 基本設計書

## 1. 文書情報

- 対象: 現行実装（文書同期時点 `v0.1.41`）
- 更新基準日: 2026-08-25
- **現行ソースコードを正とする。** 本書は構成・責務・主要設計原則をコードから要約したもの。
- 具体的な実効値は `現行仕様書.md`、モジュール単位の詳細は `詳細設計書.md` を参照する。

## 2. システム概要

City-SimはTypeScript / three.js / Viteで構成するブラウザ向けリアルタイム都市シミュレーションである。

静的な都市表示ではなく、次の状態を同一simulation time上で相互作用させる。

- 都市計画、道路、Block/Parcel、建物、POI
- 市民、欲求、勤務、食事、買物、娯楽
- 徒歩、自家用車、バス、物流
- 道路信号、歩行者信号
- 在来鉄道、鉄道旅客、駅、車両基地
- 外部接続高速鉄道と来訪者
- 昼夜環境、Inspector、Performance/UI

## 3. 設計原則

### 3.1 コード優先

設計書は実装の上位契約ではない。コードと文書が食い違った場合はコードを読み、実効挙動を確定してから文書を直す。

Prototype Patchを使う分野では「base classに書かれている値」ではなく、**最終import後に有効になるoverride**を実効仕様とする。

### 3.2 データ指向

大量Agent/VehicleはSoA TypedArrayで保持する。大量オブジェクトを1Agent=1classで持たない。

Cross-Origin Isolationが使える場合はSharedArrayBufferを利用し、Workerが大規模配列へ直接アクセスする。

### 3.3 Coordinator / Store / System

- Store: 大量状態を保持
- System: Storeを走査して局所ロジックを更新
- World: 行動、POI、モード切替、複数System間の状態遷移を統合
- Renderer: stateをthree.jsへ同期

鉄道だけは現状 `RailRenderer` が運行状態まで持つため、この分離が完全ではない。

### 3.4 Simulation / Rendering分離

Simulation stepと描画frameを分離する。高倍率時にsimulation処理が遅延しても、描画loopへ無制限のcatch-upを押し込まない。

Railは `RailFrameScheduler` が独自budgetを持つ。

### 3.5 GPU Instancing

建物、道路設備、歩行者、道路車両、鉄道設備、駅部材、列車等はInstancedMesh/primitiveを基本とする。

## 5. ソース領域の責務

### `src/core`

SimulationClock、SpatialHash、math等。ドメイン固有責務を増やさない。

### `src/config`

JSON設定、値域検証、Seed解決。

### `src/generation`

都市計画、道路・Block/Parcel・建物、特殊施設、公園、鉄道計画、駅周辺clearance。

### `src/agents`

AgentStore、Need、Utility AI。

### `src/traffic`

Road/Sidewalk network、A*、VehicleStore、Traffic、Signal、Bus、Logistics、旋回tuning。

### `src/world`

Agent action lifecycle、POI reserve/release、徒歩/車/バス/鉄道の遷移、鉄道旅客sidecar/需要/統計。

### `src/rendering`

都市3D、RailRenderer、駅/列車拡張、外部高速鉄道、Inspector、Dashboard、Performance、filter/window管理。

## 6. 都市モデル

都市計画はCBD、副都心、用途地区、地価、密度、駅影響を持つ。道路がBlock/Parcelと移動の骨格になる。

鉄道計画はTOD用のplanned stationを先に持つが、最終running lineは道路生成後にRoad A*へ合わせる。

### 駅周辺の土地利用

駅周辺を無条件に公園化しない。実線路のclearanceだけ建物を除去し、Central/SubCenterの安全な駅前建物は低層商業へ寄せる。

## 7. 交通モデル

### 徒歩

SidewalkNetworkと歩行者信号を使用。高負荷時はPedestrian Workerが共有Agent座標を更新する。

### 自家用車/トラック/バス

RoadNetworkのEdge上でIDM系追従、信号、占有を処理する。

交差点のworld poseは `TrafficTurningTuning` が連続Bezier曲線へ置換し、位置とheadingを同じ軌跡から得る。道路交通の論理占有は引き続きEdgeベース。

## 8. 鉄道計画設計

### 8.1 計画座標と走行線形を分ける

駅のplanned/physical/access座標と、列車が走る `line.path` を同一視しない。

`line.path` は道路A* Node列を正とし、駅設備位置のために道路外へ引き込まない。これにより「駅は道路へ無理に曲げないが、線路は道路沿い」という要件を実装している。

### 8.2 線形平滑化

近共線点のみ削除し、90度超の鋭角だけ複数点化する。大きな道路ショートカットを許容する旧回廊簡略化は使わない。

### 8.3 支線

支線は幹線駅をjunctionとし、短すぎる1駅stubを生成しない。支線の描画railと列車offsetは同じ関数を使用する。

## 9. 鉄道運行設計

RailRendererは現在次を所有する。

- smooth lines
- train runs
- block occupancy/reservation
- route reservation
- timetable
- signal/turnout state
- depot/terminal state

列車編成は単一の `run.distance` を位置基準とする。個別車両を別simulationで追従させない。

幹線は右側通行。異常時のみ反対線routeを予約できる。

ダイヤは15秒quantum。回送は `deadhead` flagで営業列車と分離する。

## 10. 駅設計

### 10.1 Geometry ownership

`RailStationArchitecture` がvisible platform slab / canopy / wall / equipmentを所有し、legacy platform/roofは抑止する。

### 10.2 曲線駅

駅設備は最終smooth railへ追従する。緩曲線は許容するが、線路とは別の独立直線へホームを置かない。

### 10.3 物理基準の共有

待避線では以下が同じ最終offsetを使うことを不変条件とする。

- island platform設計
- siding rail
- sidingを走るLocal train

現行実効offsetは10.4 m。

### 10.4 駅設備

ベンチ、自販機、蛍光灯、PointLight、発車案内板をprocedural生成する。発車案内板は実運行時刻・停車判定を参照し、ダイヤロジックを別実装しない。

## 11. 鉄道旅客設計

WorldはRailRendererの全内部へ直接依存せず、Transit Provider/Bridgeで乗車可能列車・列車位置・station accessを取得する。

鉄道固有stateはWorld-side sidecarへ持つ。駅へteleportせず3D routeでホームへ到達してから実列車へ乗る。

## 12. 外部高速鉄道

外部高速鉄道は在来RailRendererと別のsubsystem。運行、中央駅停車、旅客量、Visitor交換を持ち、Registryを介してInspectorへsnapshotを公開する。

UIへ固定statusを常駐させず、選択/追跡時のInspectorを情報入口とする。

## 13. 描画フィルター設計

描画カテゴリをparent `THREE.Group`で包み、childが内部で`visible=true`へ戻しても親がOFFなら描画されない構造とする。

`線路・駅設備` と `列車` は別カテゴリ。列車カテゴリには在来列車外装、前照灯、外部高速列車を含める。

Filterはsimulation停止機能ではない。

## 14. UIウィンドウ設計

既存panelの中身を書き換えるのではなく、外側に共通window shellを付ける。

対象:

- 統計HUD
- 時間/速度
- 描画フィルター
- Performance
- 追跡情報

Shellがdrag、resize、z-order、close、viewport clamp、localStorage persistenceを担当する。右下`UI` launcherからGUI操作でき、keyboard shortcutは補助として残す。

## 15. Performance設計

- SharedArrayBuffer / Worker
- dirty/active list
- spatial index
- A* route cache
- GPU instancing
- LOD
- rail frame budget
- render/simulationの個別計測

描画フィルターで見えないdynamic visual syncを一部skipできるが、simulation benchmarkと通常表示benchmarkを混同しない。

## 16. 重要な不変条件

1. 列車編成位置は `run.distance` が唯一の基準。
2. dwell中に到着ホーム/laneを瞬間変更しない。
3. 物理信号を非表示にしてもblock/route reservationを消さない。
4. 支線列車は描画支線railと同じoffset関数を使う。
5. 駅ホームはrunning railと別軌跡にしない。
6. Station access stairは道路上で高度を下げず、長い斜め線路横断を作らない。
7. Rail patch import順を変更する場合は最終overrideを再確認する。

## 17. 技術的負債

- RailRendererのoperation/render責務混在
- Prototype Patchの順序依存
- base classと最終runtime constantの二重化
- station geometry/access modelの重複
- `railStationSpacing`の既定値1.5倍処理が明示configに負ける状態
