# City-Sim 詳細設計書

## 1. 文書情報

- 対象: 現行実装（文書同期時点 `v0.1.41`）
- 更新基準日: 2026-08-25
- **ソースコードを正とする。**
- 本書は全private methodの逐語説明ではなく、変更時に最終override・定数・不変条件・影響範囲を判断するための実装設計書である。

## 2. 起動/更新

### `src/main.ts`

主責務:

- config読込とSeed解決
- World生成
- Loading中PreRoll
- three.js Renderer/Scene/Camera/環境光構築
- EnhancedRenderer / RailRenderer / TrainLiveryOverlay構築
- Inspector / Dashboard / Performance構築
- simulation batch scheduling
- RailFrameSchedulerへのrail sim seconds投入
- render cadence調整
- follow/camera更新
- FPS/HUD更新

`APP_VERSION` は `src/version.ts` から取得し画面左下へ表示する。

### `src/version.ts`

現在、バージョン値だけでなくruntime tuningのimport入口でもある。

```ts
RenderFilterTuning
RenderFilterRailSplit
UiNoiseReduction
```

このためversion fileのimport削除は単なる表示変更ではなく挙動変更になる。

### `src/boot/PreRoll.ts`

Loading画面中に通常World stepを事前進行し、表示開始直後の全Agent Idle/routing burstを消化する。

## 3. 設定

### `src/config/CityConfigLoader.ts`

Merge順:

```text
DEFAULT_CONFIG
  <- raw top-level config
planning:
  DEFAULT_CITY_PLANNING
    <- raw planning config
```

値域検証後、明示されたJSON planning値はdefaultより優先される。

### 駅間隔の重要な実装差

`RailPlanningEnhancements` はmodule load時に:

```ts
DEFAULT_RAIL_PLANNING.railStationSpacing *= 1.5
```

を行うが、`public/config/city.json` が `railStationSpacing: 525` を明示し、Loaderがその値をplanning optionsへ入れる。最終 `RailNetworkPlan` constructorもoptionsをdefaultへ上書きするため、通常起動の実効値は525 m。

この挙動を変更する場合はdefaultだけでなくconfig/merge pathまで確認する。

## 4. World/Agent

### `AgentStore.ts`

SoA store。Cross-Origin Isolation + SharedArrayBuffer利用可能時はshared backingを使う。

主要state:

```text
Idle / Routing / Traveling / Engaged
ToVehicle / Driving
ToBusStop / WaitingBus / OnBus
ToRailStation / WaitingTrain / OnTrain
```

### `World.ts`

Coordinator責務:

- Utility decision
- POI reserve/release
- trip開始/完了
- walk/drive/bus遷移
- Traffic/Signal/Bus/Logistics呼び出し
- Worker batch
- activity snapshot

鉄道旅客機能はpatch/sidecarでWorldへ統合する。

## 5. Worker/A*

### Pedestrian Worker

Shared snapshot + linked-cell indexを利用する。Worker内barrierでindex build→avoid/moveをつなぎ、対応環境ではmain側完了待ちに `Atomics.waitAsync` を使う。

### A*

検索ごとの全work-array fillを避け、touch nodeだけを初期化する。静的graphのstart/goal pairにLRU route cacheを持つ。

Road/Sidewalk graphをruntime変更する機能を追加する場合はcache invalidationが必要。

## 6. 道路車両

### `TrafficSystem.ts`

論理走行はRoad Edgeベース。VehicleStoreのpath/pathCursor/segT/segLenを進め、signal/IDM/occupancyを処理する。

### `TrafficTurningTuning.ts`

`TrafficSystem.prototype.updateWorldPos` と `update` をpatchする。

#### Turn curve

Intersection indexの前Edge/後Edgeからlane centerを取り、三次Bezier:

```text
P0: incoming lane, intersection手前
P1: incoming tangent
P2: outgoing tangent
P3: outgoing lane, intersection後
```

を作る。

Turn radius:

```text
car   10.5 m
truck 15.0 m
bus   18.0 m
```

角度15度未満はcurve化しない。

`updateWorldPos` はcurve zoneならcurve pose、そうでなければstraight lane poseをVehicleStoreへ書く。

#### Speed cap

Upcoming/previous curveからcorner speedを求め、`vs.maxSpeed` を一時的に下げてbase TrafficSystem updateを呼ぶ。Edgeが変わっていなければupdate後に元maxSpeedを戻す。

IDMやsignalを置換しないことが重要。

### `VehicleVisualSmoother.ts`

`TrafficTurningTuning` をimportし、simulation batch間の見た目だけを補間する。position/rotation follow rateはrotationをやや速くし、curved positionにheadingが遅れて横滑りに見えないようにする。

## 7. 鉄道計画

### `RailPlanning.ts`

基本型:

```text
RailStation
  id/name
  plannedX/plannedZ
  x/z
  kind
  lineIds
  roadNode
  busStopId
  influenceRadius (augmentation)

RailLine
  id/name/kind
  stationIds
  path
  cumulative
  length
```

base classのコメントやbase `alignToRoadNetwork()` に旧挙動が残る場合があるが、現行実効動作は後段 `RailPlanningEnhancements` を正とする。

### `RailPlanningEnhancements.ts`

#### Default tuning

- trunk linesを最低3へ補正
- default station spacingを×1.5するコードあり。ただし通常config明示525が最終優先

#### `alignToRoadNetwork()` 最終override

Station:

- nearest surface road nodeを `roadNode` へ設定
- Terminalはstation metadataとしてland pointを保持可能
- 既存park/open-space内stationはplanned coordinateをmetadataとして保持可能
- その他はroad node座標へstation x/zを合わせる

Line:

- station間Road A*を実行
-成功時はNode座標列をsegmentとする
- A*失敗時も可能なら両端roadNode座標を使う
- station x/zをrunning pathへ挿入しない
- `compressCollinear()` でnear-collinear road pointsのみ除去

旧38m/28m deviation simplificationやstation S-approachは使用しない。

### `RailCurveTuning.ts`

`makeSmoothLine()` の入力pathだけ一時置換する。

90度を超えるsource turnをentry/exit + quadratic samplesへ分割し、base smooth処理を実行。その後元 `line.path` を復元する。

## 8. 支線

### `RailSpurConsistency.ts`

`RailNetworkPlan.prototype.buildSubCenterSpur` 最終override。

- trunk stationだけjunction候補
- non-terminal優先
- `standardSpacing = max(320, railStationSpacing * 0.90)`
- short candidateはjunction station昇格だけで終了
- real spurは `segmentCount=max(2, ceil(length/standardSpacing))`
- junction + intermediate(s) + SubCenter

RailRenderer側:

- `sharedStationSafePath()` は `line.path` をそのままcopyして返す
- spur `trainTrackOffset()` は `trackOffsetAt(smooth, 0, distance)` を直接返す

これにより描画rail/列車poseの不一致を防ぐ。

## 9. RailRenderer core

### `RailRenderer.ts`

operations + renderingの両責務を持つ。

主要state:

```text
smoothLines / lineY
trainRuns
blocks
blockOccupancy / blockReservations
routeReservations / plannedRoutes
railSignals / turnoutIndicators
RailTimetable
train instance meshes
```

### TrainRun invariant

**編成位置の唯一のsimulation基準は `run.distance`。**

Car pose:

```text
run.distance + consist car offset
  -> front/rear bogie sample on train track
  -> position + heading
```

車両ごとの独立follow controllerを導入しない。

## 11. Right-hand / signals / terminal

### `RailRightHandOperation.ts`

正規laneは `-direction`。dwell中lane固定。exception routeだけreverse-runningを許可。

### `RailSignalPlatformClearance.ts`

platform内部の物理signal meshを抑止するがblockは削除しない。

### `RailRendererEnhancements.ts`

terminal 4-track fan等を提供する。base/older constantが残っていても後段station runtimeで変更される値があるため、最終実効値は後段を確認する。

### `RailDepotPlacement.ts`

real `RailStationKind.Terminal` をdepot hostに限定。shared terminalはdedupeし、支線runはnearest real terminalを共有可能。

## 12. 駅運用runtime

### `RailStationOperationsTuning.ts`

主な最終化前tuning:

```text
terminal platform min 270 m
turnout speed 50 km/h
siding speed 70 km/h
approach brake 4.2 km/h/s相当
```

- terminal stopping distanceを編成長へ合わせる
- legacy canopy pieceを破棄
- passing loop手前の速度制御を修正
- service closed / retire trainをdeadhead化
- depot releaseをdeadhead化
- deadheadはendpointのみstop
- deadhead terminal dwell 5秒
- Inspector state labelを回送系へ変更

同file内に`SIDING_OFFSET=10.0`があるが、**最終実効値ではない**。

### `RailStationRuntimeV033.ts`

このmoduleが後段で最終station runtimeを確定する。

```text
TIMETABLE_QUANTUM = 15 s
MAIN_OFFSET = 1.72 m
SIDING_OFFSET = 10.4 m
```

- class-level `SIDING_OFFSET` を10.4へ設定
- normal dwellを15秒単位へquantize
- scheduled arrival/departureを15秒単位へquantize
- depot release departureも15秒単位
- physical siding railを10.4 profileで再実装
- Local train siding offsetも同じ10.4 profileへ強制

したがって島式外側線の設計値は10.4 mを正とする。

## 13. Rail timetable

### `RailTimetable.ts`

```text
CYCLE_SECONDS = 180
QUANTUM_SECONDS = 15
```

Terminal slot pattern:

```text
limited: [0]
rapid:   [30, 90, 150]
local:   [15, 45, 75, 105, 135]
```

line/direction/train ordinalでphaseをずらす。

`dispatchKey()` はscheduled departureを基準にterminal/service priority、遅延、waitingを加味してroute reservation順を決める。

Timetableはblock/signal開通そのものを決めない。

## 14. Station architecture

### `RailStationArchitecture.ts`

最終visible station geometryを生成する。

Constants:

```text
MAIN_OFFSET                1.72 m
SIDING_OFFSET              10.4 m
TRAIN_HALF_WIDTH            1.50 m
PLATFORM_CLEARANCE          0.48 m
PLATFORM_TOP_HEIGHT         1.05 m
PLATFORM_SLAB_THICKNESS     0.56 m
ROOF_CENTER_HEIGHT          4.45 m
ROOF_THICKNESS              0.18 m
TERMINAL_MIN_LENGTH       270 m
```

Platform width:

```text
terminal                    4.8 m
central/subcenter base       4.2 m
other base                   3.8 m
island add                   0.2 m
side add                     0.4 m
```

`stationPoint()` は `offsetPoint(smooth, distance, offset)` を使うため、platform/roof/equipmentは実smoothed running lineへ追従する。

`withoutLegacyPlatformAndRoof()` がlegacy material colorを捕捉し、旧platform/roofを追加しない。

生成設備:

- platform slab
- canopy
- pillar
- thin lower wall / glass / fascia
- benches/backrests
- vending machines
- emissive fluorescent fixtures
- PointLight per platform

PointLight intensity:

```text
night >=17:00 or <06:30 : 58
dusk  16:00-17:00 / 06:30-07:00 : 22
day                         : 2.5
```

## 15. Platform departure boards

### `RailPlatformIndicators.ts`

Board:

```text
frame 1.85 x 0.68 x 0.14 m
display 1.70 x 0.55 m
center height 3.72 m
platform axisに対して90度
```

- ceiling hanger x2
- up to 3 departures

## 16. Rail lighting / train livery

### `RailLightingAndIndicators.ts`

- track visible lights spacing約115 m
- green departure indicator
- blinking amber approach indicator、約280 m
- first/last car matrixからvisible head/tail lamp pair配置

一部older helperには8.0 m siding constantが残るが、最終physical siding/train alignmentは後段RuntimeV033の10.4 mを正とする。older indicator placementを修正する場合はこの差を確認する。

### `TrainLiveryOverlay.ts`

RailRenderer proxy matrixをvisible:

- shell
- windows
- route stripe
- service stripe

へ転写。

Visible front lampsに加え、最大12編成分のSpotLight poolを持つ。SpotLight targetは列車前方へ向け、時間帯でintensity変更。

Overlayは独自のtrain path interpolationを行わない。

## 17. 鉄道旅客

### `RailPassengerIntegration.ts`

World別sidecarにboard/alight/line/train/access/route等を保持する。

Transit Provider経由で:

- boarding trains
- train position
- station accesses

を取得する。

Rail routeはdirectまたは1 transfer。Station accessは3D point route。

### Stair patches

- adjacent rail levelを接続
- 長い斜めline crossingを作らない
- road上でheightを下げない
- road外へsame-height bridgeで逃がしてからground stair

### `RailPassengerMetrics.ts`

OnTrain Agentをtrain spatial indexへ対応付け、train passenger countを集計。全Agent×全train総当たりを避ける。

## 20. Render filters

### `RenderFilterTuning.ts`

Base categories:

```text
ground
roads
buildings
rail
vehicles
agents
```

各categoryはscene直下のparent Groupへ収容。StateはlocalStorageへ保存。

道路車両/Agent等はhidden中、一部visual syncをskipする。

### `RenderFilterRailSplit.ts`

追加category `trains` をbase `rail` から分離。

Adopt対象:

- RailRenderer train proxy meshes
- TrainLiveryOverlay shell/windows/stripes/headlamp
- headlight SpotLights
- external high-speed car meshes

Base panelの`rail` labelを `線路・駅設備`へ変更し、`列車` checkboxを追加。

Preset:

```text
全表示
鉄道一式
道路のみ
鉄道+道路
線路のみ
列車のみ
```

Train visibilityは専用localStorage keyで保存。

## 22. Performance Monitor

Frame/Pre/Render/GPU/SIMを分離し、Worker/Ped/Traffic/Bus/Logistics/A*/Rail/LOD等を内訳表示する。

Windowは通常hidden。P shortcutとUI launcherの両方から表示可能。

Render filter使用時は通常全表示時とrender負荷が変わるため、計測条件を記録する。

## 23. 変更時に守る不変条件

1. Train consistは `run.distance` を唯一の位置基準にする。
2. Dwell中のarrival lane/platformを保持する。
3. Signal mesh visibilityとblock safetyを分離する。
4. Running `line.path` をstation metadataへ引っ張らない。
5. Spur trainとphysical spur railは同じoffset functionを使う。
6. Island sidingは最終10.4 m基準を共有する。
7. Station visible geometryはsmoothed running lineへ追従する。
8. Ground stairはroad上で下降しない。
9. Render filterはsimulation stop機能にしない。
10. Rail patch import順変更時は、全wrap/overrideのcapture順を再監査する。

## 24. 技術的負債

- RailRendererのoperation/render混在
- Prototype patch chainの長さ
- base source comments/constantsとfinal patchの不一致
- station geometry/access情報の重複
- `railStationSpacing` default multiplierとexplicit configの優先順位不整合
- External high-speed railが在来rail subsystemと別実装
