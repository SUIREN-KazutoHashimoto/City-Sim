# 2. generation/CityGenerator.ts

## enum BuildingArchetype

建物用途とは独立した建築形状分類。

- DetachedHouse
- TownHouse
- LowRiseApartment
- MidRiseApartment
- ResidentialTower
- SmallOffice
- OfficeSlab
- OfficeTower
- SmallShop
- RetailBox
- CommercialBlock
- MixedUse
- LeisureHall

## enum RoofType

- Flat
- Gable
- Hip
- Mechanical

## interface Building

既存のid/x/z/width/depth/floors/categoryに以下を追加。

- `archetype: BuildingArchetype`
- `roofType: RoofType`
- `palette: number`
- `styleSeed: number`
- `rotation: number`
- `urbanity: number`

## constructor(cfg)

Noise/RNGをseedから初期化し、都市サイズを保持する。

## urbanization(x,z)

**戻り値**: 0..1

FBMノイズと中心距離減衰を合成しclampする。

## calibrateThreshold()

64×64でurbanizationをサンプリングし、urbanRatioTargetに対応する分位点をurbanThresholdへ設定する。

## generate()

1. 閾値校正
2. RoadNode生成
3. 格子方向RoadEdge生成
4. `ensureConnected()`
5. 市街地Blockへ`fillBlock()`
6. `buildGates()`

## ensureConnected(nodeGrid, cols)

Union-Find相当で連結成分を抽出し、小成分を最大成分へ同一行/列道路で接続する。

## buildGates(nodeGrid, cols, bs, size)

都市四辺中心付近の既存Nodeから盤外NodeへHighwayを生成し、gateNodesへ追加する。

## fillBlock(ox,oz,bs,urban)

**主要変更点**:
1. 駐車場配置判定
2. category選択
3. 基本階数/寸法生成
4. `pickArchetype()`
5. `adjustFloors()`
6. アーキタイプ別footprint補正
7. `pickRoofType()`
8. palette/styleSeed/rotation生成
9. Building追加
10. `registerPOIs()`

## addParking(x,z,size)

物理スロット配列を生成しParking POIと関連付ける。

## takeSlot(poiId)

最初のfree slotを0へ変更してindexを返す。空きなしは-1。

## giveSlot(poiId,slot)

対象slotをfree=1へ戻す。

## slotX / slotZ

POI/slotから物理座標を返す。

## pickCategory(urban)

都市化度に応じた用途確率分布から主用途を返す。

## pickArchetype(cat,urban,floors,w,d)

用途、都市化度、階数、縦横比、乱数から建物形状分類を選ぶ。

## adjustFloors(type,floors)

アーキタイプごとに最低/最大階数を補正する。Tower/MixedUseは最低階数を保証する。

## pickRoofType(type)

戸建系はGable/Hipを高確率、Tower系はMechanical/Flatを中心に返す。

## registerPOIs(buildingId,x,z,cat,floors,archetype)

主用途POIを生成する。

MixedUseでは追加Retail、確率Food、必要に応じてHome/Workを同一buildingIdで追加する。

# 3. rendering/EnhancedRenderer.ts

## class EnhancedRenderer extends InstancedRenderer

既存Rendererのpublic APIとRaycast対象を維持しつつ、追加InstancedMeshを重ねる。

### constructor(scene)

`super(scene)`を呼び、追加Mesh用Scene参照を保持する。

### buildStatic(buildings,net,sidewalk,lots)

1. 元のBuilding[]を`super.buildStatic()`へ渡して全高の建物hit proxyを生成。
2. 代表建物MeshのMaterialを透明化し、Raycast専用とする。
3. `buildingDetails()`で可視建物を構築。
4. `buildRoadDetails()`
5. `buildParkingMarkings()`
6. `buildStreetFurniture()`

**副作用**: Sceneへ静的InstancedMeshを追加する。

### buildAgents(capacity)

`super.buildAgents()`でInspector用代表Capsuleを構築して透明化した後、可視形状としてTorso/Head/Leg用InstancedMeshを構築する。

### syncAgents(store,simTime=0)

表示対象AgentをStore順に走査する。

- Torso位置/向き同期
- ID/occupationから服色選択
- Head同期
- 移動速度>0.05の場合、sin波で左右脚を逆位相に回転
- Driving/Engaged/OnBusは非表示

各Mesh.countを可視数へ更新する。

### buildVehicles(capacity)

既存車体代表Meshに加えて以下の動的InstancedMeshを生成する。

- vehicleCabin
- vehicleWheels (capacity×2)
- vehicleFrontLamp
- vehicleRearLamp

### syncVehicles(vs)

既存`super.syncVehicles()`後に同じ表示条件でStoreを走査する。

自家用車:
- ID/colorIdxから4形状を選択
- cabin寸法を変更

Bus:
- len=11, width=2.45相当
- 長いwindow/cabin volume

Truck:
- len=9, width=2.4相当
- 前方寄りcabin

共通で前後axle、head/tail lampを同期する。

### buildBusStops(stops)

`super.buildBusStops()`後、偶数index停留所にroof/back/benchを追加する。

### buildingDetails(buildings)

部品配列を先に作成し、部品種別ごとにInstancedMesh化する。

- shells: 既存台座を覆う用途パレット外装
- uppers: Tower/MixedUse上層
- frontPanels / sidePanels: ガラス面
- roofs: Gable/Hip風4角Cone
- rooftop: 機械設備
- awnings: 商業系庇

Tower上層幅/奥行きにはstyleSeed由来の差を加える。

### buildRoadDetails(net)

undirected edge重複を除外する。

- non-Highway -> 道路両側curb
- Arterial lanes>=2 -> median
- Highway -> guard rail

道路Graph/交通ロジックは変更しない。

### buildParkingMarkings(lots)

各物理slotの左右へ区画線を生成する。

`MAX=30000`で部品数を制限する。

### buildStreetFurniture(sw)

SidewalkEdgeの重複とcrossingを除外して間引き配置する。

- 5系列ごと: street light
- 11系列ごと: tree

上限:
- poles < 1800
- trunks < 900

### baseFloors(b)

OfficeTower=最大4階、ResidentialTower/MixedUse=最大3階を台座とする。その他は全階をbaseとする。

### dims(b)

rotation有無でwidth/depthを入れ替える。

### buildingColor(b)

category別paletteから`b.palette`で色を取得する。

### addStatic(geometry,material,parts,colors=false)

StaticPart[]を1つのInstancedMeshへ変換しSceneへ追加する共通ヘルパー。

### matrix(...)

静的部品用Matrix4を生成する。

### pose(...)

Store上の位置/headingとlocal offsetから動的部品のMatrixを生成し、対象instanceへ設定する。

# 4. rendering/InstancedRenderer.ts

既存の互換描画レイヤ。

主要メソッド:

- `buildStatic()`: 地面/道路/歩道/駐車場/建物
- `buildAgents()`: Agent代表Capsule
- `buildVehicles()`: Vehicle代表Box
- `buildSignals()`: 信号設備/灯器
- `buildCrosswalks()`: 横断歩道
- `buildStopLines()`: 停止線
- `buildBusStops()`: 停留所ポール/標識
- `buildGates()`: 外部ゲート
- `syncAgents()`: Agent代表Mesh同期
- `syncVehicles()`: Vehicle代表Mesh同期
- `syncSignals()`: 灯色同期

EnhancedRendererはこのAPIを壊さない。

# 5. main.ts

## 初期化

`InstancedRenderer`ではなく`EnhancedRenderer`を生成する。

従来と同じ順序でbuildStatic/buildAgents/buildVehicles/buildSignals/...を呼び出す。

## updateEnvironment()

**入力**: `world.clock.dayPhase`

1. `solar = sin((phase-0.25)*2π)`
2. daylight/twilightを0..1へ正規化
3. night/dusk/day skyをlerp
4. background/fog色を更新
5. sun強度/色/位置を更新
6. hemisphere強度を更新

## frame(now)

従来処理に加え、Agent同期へ`clock.totalSeconds`を渡して簡易歩行アニメーションを進める。

`updateEnvironment()`はpause中も現在時刻の表示状態を保つため毎描画frame実行する。

# 6. agents/AgentStore.ts

今回の描画アップグレードではStore項目を追加しない。

外観色/歩行位相はAgent ID、occupation、simTimeから描画側で生成する。

これによりAI/保存データへの影響を抑える。

# 7. traffic/VehicleStore.ts

今回の描画アップグレードでは車種enumをStoreへ追加しない。

自家用車の描画タイプは `vehicle id + colorIdx` から決定し、交通性能パラメータとは分離する。

Bus/Truckは既存`isBus`/`isTruck`を使用する。

# 8. world/World.ts 主要メソッド

## populate(count)

Home/Work/車保有/駐車場を割当て、市民/車両Storeへ生成する。

## step(dtSec)

Signal -> Need -> Utility -> Routing -> Traffic -> Bus -> Logistics -> Walk -> ArrivedVehicle -> Activity の順に更新する。

## beginTrip(i)

POI予約後、距離/energy/車保有/バス路線から移動方式を決定する。

## startDriving(i)

目的地駐車場へのdispatchを行い、成功時は出発駐車場を解放する。

## assignWalkPath(i,tx,tz)

SidewalkNetwork最寄Node間でwalk A*を実行する。

## walkStep(i,dt)

横断信号、交差点車両、簡易歩行者分離を処理し移動する。

## handleArrivedVehicles()

到着車両を駐車スロットへ移し、市民を徒歩状態へ戻す。

## activity(i,now,dt)

POIカテゴリに応じた欲求/wealth回復と在庫消費を行う。

# 9. traffic主要クラス

## AStar.findPath(start,goal)

PathGraph上でA*を実行する。driveは時間コスト、walkは距離コスト。

## TrafficSystem.dispatch(...)

RoadNetwork最寄Nodeから経路を生成してVehicleをDrivingへ遷移させる。

## TrafficSystem.update(dt)

Edge occupants再構築、segTソート、IDM加速度、信号/歩行者停止、Edge遷移、到着判定を行う。

## SignalSystem.update(dt)

各信号のphase timerを進める。

## BusSystem.update(...)

停留所到着時に降車/乗車/停車時間を処理し、次停留所へdispatchする。

## LogisticsSystem.update(dt)

idle/toStore/unloading/returningの状態機械を進める。

# 10. 設計上の注意

- EnhancedRendererの追加MeshをInspectorのRaycast対象へ直接加えない。代表MeshとのinstanceId対応が崩れるため。
- Building.styleSeedは外観専用とし、Utility AI等のシミュレーション判断へ流用しない。
- 静的装飾を増やす場合は必ずInstancingと上限を設計する。
- Tower系の台座/上層分離は描画表現であり、POI座標/容量は建物単位のままとする。
- 将来車種ごとに走行性能を変える場合は、描画派生値ではなくVehicleStoreへ正式なvehicleTypeを追加する。
