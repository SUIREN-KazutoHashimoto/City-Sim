# City-Sim 詳細設計書

## 1. 文書情報

- 対象プロジェクト: City-Sim
- 対象ソース: `develop` ブランチ現行実装
- 目的: 現行ソースコードをメソッド単位で整理し、入力・出力・主処理・副作用・注意点を定義する。
- 本書は実装解析ベースであり、ソース改修時は対応する記述も更新する。

# 2. `src/main.ts`

## `clockIcon(h)`

- 入力: 時刻 `h`
- 出力: 時間帯を表す文字列
- 処理: 5-7時、7-17時、17-19時、19-22時、その他で表示を切り替える。
- 副作用: なし。

## `updateEnvironment()`

- 入力: `world.clock.dayPhase` を内部参照。
- 出力: なし。
- 処理:
  1. `solar = sin((phase-0.25)*2π)` を算出。
  2. daylight / twilight を0..1へ正規化。
  3. night / dusk / day の背景色を補間。
  4. Scene background / Fog colorを更新。
  5. DirectionalLightの位置・強度・色を更新。
  6. HemisphereLightの強度を更新。
- 副作用: three.js SceneとLight状態を変更する。

## `frame(now)`

- 入力: `requestAnimationFrame` の時刻。
- 出力: なし。
- 処理:
  1. フレーム実時間差と平滑化FPSを算出。
  2. 非pause時に `clock.advance()`。
  3. 返却step数だけ `world.step(stepDt)`。
  4. Agent / Vehicle / Signalを描画へ同期。Agent同期には`clock.totalSeconds`を渡す。
  5. Dashboardをsample。
  6. `updateEnvironment()`。
  7. カメラ追跡、Inspector、Dashboard更新。
  8. Sceneを描画。
  9. 時計・HUDを更新。
  10. 次のRAFを登録。
- 副作用: シミュレーション全体更新、DOM更新、描画。

# 3. `src/core/math.ts`

## `clamp(v, lo, hi)`

- 入力: 値、下限、上限。
- 出力: 範囲内へ丸めた値。
- 副作用: なし。

## `lerp(a, b, t)`

- 入力: 始点、終点、補間率。
- 出力: 線形補間値。

## `dist2(ax, az, bx, bz)`

- 出力: 2点間距離の二乗。
- 用途: 平方根不要な比較。

## `dist(ax, az, bx, bz)`

- 出力: 2点間ユークリッド距離。

## `makeRng(seed)`

- 入力: 32bit seed。
- 出力: 0以上1未満の値を返す疑似乱数関数。
- 処理: seed状態を内部に保持する軽量PRNG。
- 注意: `Math.random()` と併用されているため、プロジェクト全体としては完全決定論ではない。

# 4. `src/core/SimulationClock.ts`

## `constructor`

暗黙初期値:

- `timeScale = 60`
- 開始時刻 = 8:00
- `fixedStep = 1/30`
- `maxSubSteps = 40`

## `advance(realDeltaSec)`

- 入力: 現実経過秒。
- 出力: 実行すべきstep数。
- 処理:
  1. deltaを0.1秒以下へ制限。
  2. timeScaleを掛けaccumulatorへ加算。
  3. 必要step数が40以下なら固定1/30秒ずつ消費。
  4. 40超ならaccumulator全体を40分割し `stepDt` に設定。
  5. `_totalSeconds` を更新。
- 副作用: シミュレーション時刻、accumulator、stepDtを更新。

## `totalSeconds` getter

総シミュレーション秒を返す。

## `hour` / `minute` / `second` getters

現在日の時刻要素を返す。

## `hourF` getter

小数を含む0-24時間値を返す。Utility AIの時間判定で使用。

## `dayPhase` getter

1日を0-1で表す。昼夜環境更新でも使用する。

## `day` getter

開始からの経過日数。

## `format()`

`Day N HH:MM` 形式を返す。

## `constructor(cfg)`

- `ValueNoise2D`、seed付きRNGを生成。

## `urbanization(x, z)`

- private。
- fBmと都市中心からの距離減衰を合成。
- 出力を0-1へclamp。

## `calibrateThreshold()`

- private。
- 64×64地点をsample。
- `urbanRatioTarget` に対応する分位点を `urbanThreshold` とする。

## `generate()`

- 都市生成のメイン処理。
- 処理:
  1. 閾値調整。
  2. 市街地は密、郊外は3格子おきにRoadNode生成。
  3. 行・列方向に道路接続。
  4. `ensureConnected()`。
  5. 市街地blockへ `fillBlock()`。
  6. `buildGates()`。
- 副作用: `net`, `buildings`, `poi`, `parkingLots`, `gateNodes` を構築。

## `ensureConnected(nodeGrid, cols)`

- private。
- Union-Find相当で道路連結成分を抽出。
- 最大成分以外について、同一行/列上の最寄本体nodeへArterial道路を追加。

## `buildGates(nodeGrid, cols, bs, size)`

- private。
- 四辺中央付近の道路nodeを探索。
- 都市外120m位置へHighway nodeを追加し接続。
- gate node IDを `gateNodes` へ格納。

## `fillBlock(ox, oz, bs, urban)`

- private。
- 街区内をparcel化。
- 一部を駐車場または空地とする。
- 建物主用途、基本寸法、基本階数を生成。
- `pickArchetype()` で建築形状を選択。
- `adjustFloors()` で形状に適した階数へ補正。
- archetype / roofType / palette / styleSeed / rotation / urbanity をBuildingへ保存。
- `registerPOIs()` を呼ぶ。

## `addParking(x, z, size)`

- private。
- 約3mセルで駐車スロット座標を生成。
- Parking POI登録。
- `lotByPOI` と `parkingLots` を更新。

## `takeSlot(poiId)`

- 出力: 確保したslot index。空きなし/対象なしは-1。
- 最初のfree slotを0へ変更する。

## `giveSlot(poiId, slot)`

指定slotをfree=1へ戻す。

## `slotX(poiId, slot)` / `slotZ(poiId, slot)`

駐車slot実座標を返す。対象なし時は0。

## `pickCategory(urban)`

- private。
- 都市化度と乱数から建物主用途を選ぶ。
- urban>0.8ではWork/Retail/Food/Leisure比率を高める。

## `pickArchetype(cat, urban, floors, w, d)`

- private。
- 用途、都市化度、基本階数、footprint縦横比、乱数から建物形状を決定する。
- Homeは郊外戸建から都心住宅Towerへ連続的に変化する。
- WorkはSmallOffice / OfficeSlab / OfficeTower / MixedUseへ変化する。
- Retail/Food/Leisureも都市化度に応じて低層・商業Block・MixedUseを選ぶ。

## `adjustFloors(type, floors)`

- private。
- archetypeごとに最低/最大階数を補正する。
- Tower/MixedUseでは最低階数を保証する。

## `pickRoofType(type)`

- private。
- DetachedHouse/TownHouseはGable/Hipを中心とする。
- Tower/MixedUseはMechanical/Flatを中心とする。

## `registerPOIs(buildingId, x, z, cat, floors, archetype)`

- private。
- 主用途POIのpriceTier/capacity/stockを設定。
- MixedUseでは同一buildingIdへRetail、確率Food、必要に応じてHome/Workを追加する。
- MixedUse以外では従来どおりHomeの一部にFood、Work/Leisureの一部にRetailを追加する。

## `update(dt)`

各Truck phaseで処理を分岐。

# 29. 実装上の注意事項

1. `POI.occupancy` は純粋な在館人数ではなく予約済み利用枠を含む。
2. ParkingではPOI occupancyとslot freeを双方整合させる必要がある。
3. AgentStore / VehicleStoreの一部初期値は `Math.random()` であり、CityGenerator seedだけでは完全再現されない。
4. AStar内部配列は生成時node数固定。Network構築完了後にAStarを生成する現行順序を維持する。
5. TrafficSystemは毎updateでEdge occupantsを再構築・sortするため、車両数増加時の負荷点となり得る。
6. `World.step()` の実行順には信号→交通→歩行等の依存があるため、順序変更は挙動へ影響する。
7. Bus/TruckもVehicleStore/TrafficSystemを共有するため、通常車両向け変更が公共交通・物流にも影響する。
8. Rendererのinstance indexとStore indexは一致しない。必ず `agentMap` / `vehicleMap` を介す。
9. EnhancedRendererの可視追加MeshをInspectorへ直接RaycastさせるとinstanceId対応が崩れるため、透明代表Meshをhit proxyとして維持する。
10. `Building.styleSeed` は描画用とし、Utility AI等のシミュレーション判断へ流用しない。
11. 大量の静的ディテール追加時はInstancingと件数上限を維持する。
12. `Health` / `Education` はEnum定義済みだが現行主要フロー未接続。
13. 大規模化時はWorldの全agent走査、Traffic occupants sort、A*実行数、描画同期が主要見直し対象となる。
