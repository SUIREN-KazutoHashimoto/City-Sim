## 4. 都市生成patch chain

### 4.1 `RuralIndustryAndDepotTuning`

主な追加:

- density-aware Local road skip
- early park trim
- taxi/bus/freight depot
- rural production sites

Production kind:

```ts
'farm' | 'raw-factory' | 'processor' | 'assembler'
```

Depot kind:

```ts
'taxi' | 'bus' | 'freight'
```

### 4.2 `AgriculturalEstateTuning`

Farmをmulti-block estateへ変換。

重要field:

```text
site.x/z             warehouse / logistics source
site.fieldX/Z        visual/cultivation center
site.fieldWidth/Depth
site.officeBuildingId
site.warehouseBuildingId
site.workPoiIds
site.blocksWide/Deep
```

一般roadはplanned farm interiorを通さない。

### 4.3 `AgriculturalEstateIndexGuard`

v0.1.77 farm selector hashのsigned index互換guard。

City generation中だけArray negative-key guardをinstallし、`finally`でrestoreする。

通常Array挙動へ恒久影響を残さない。

### 4.4 `CityGenerationRefinement`

最終順:

```text
previous generation
→ station clearance
→ farm field expansion
→ park trim by height zone
```

#### Station clearance

```text
Central/SubCenter radius = 78
Local/Terminal radius    = 56
```

Building half-diagonalを加算して判定。

Retire時:

- building dimensions/areaを0化
- building POI disable
- facility registryから除外
- production siteに関係するbuildingならsiteごと除外
- farm estate registryも同期

#### Farm expansion

Candidate field expansionは:

- city bounds
- road interior collision
- building collision
- other farm overlap

をすべて通過した場合のみ採用。

Farm base production:

```ts
const area = fieldWidth * fieldDepth;
site.processRate = Math.max(6, area / 7_000);
site.outputCapacity = Math.max(6_000, Math.round(area / 3.2));
```

#### Park quota

Blockをhigh/mid/lowへ分類。

```text
high: 0.02
mid:  0.01
low:  0.05
```

Generated parkをquotaまで残し、それ以外のPOIをdisableする。

## 5. Workplace runtime

### `WorkplaceProductivityTuning`

Present worker条件:

```ts
workPOI >= 0
&& state === AgentState.Engaged
&& goalPOI === workPOI
```

Work POIごとに:

```text
present
capacity
efficiency
```

をcacheする。

Production siteは対応Work POIをaggregateし:

```text
site.presentWorkers
site.workerCapacity
site.efficiency
site.effectiveProcessRate
```

を更新する。

既存Industrial Logistics update呼出し中だけ:

```ts
site.processRate = baseProcessRate * efficiency
```

とし、呼出し後base rateへ戻す。

### `WorkplaceRosterInspectorTuning`

Assigned workerは:

```ts
store.workPOI[agent]
```

を全Agent走査してPOI別countする。

表示置換:

```text
出勤 present / 在籍 assigned / 定員 capacity / ...
```

Farmは`site.workPoiIds`をaggregateする。

## 6. Industrial Logistics

### `IndustrialLogisticsTuning`

Supply stage:

```text
source outputStage 0 → inputStage 0 processor
processor outputStage 1 → inputStage 1 assembler
assembler outputStage 2 → retail/export
```

Production:

- source site: inputなしでoutput増加
- processor/assembler: inputを消費
- conversion yield: 0.92

Truck:

```text
capacity = 240
LOAD_SECONDS = 5
UNLOAD_SECONDS = 6
fleetSize = clamp(ceil(siteCount / 3.5), 18, 72)
```

Phase:

```text
idle
toSource
loading
toDestination
unloading
returning
```

Freight depotをhomeとする。

## 7. Multi-lane traffic

### `MultiLaneTrafficTuning`

Lane runtimeはVehicleStore本体とは別管理。

Turn lane selection、lane-change progression、lane-specific occupancy/gapを追加する。

### `TurningLaneTransitionFix`

問題:

```text
turn laneを維持したい
+
outgoing road lane countへ事前mergeしたい
```

が同時に要求されると交差点手前で永久停止し得る。

修正:

- genuine turnだけ抽出
- MultiLane update中の`RoadNetwork.edgeBetween()`結果だけvirtual lane countを返す
- real `RoadEdge.lanes`は変更しない
- actual edge transition時はreal lane countへclamp

Straight lane reduction guardは維持する。

## 8. Turn visual path

### `TurningVisualPathTuning`

Base `updateWorldPos()`を先に呼び、その後turn visual zoneだけposition/headingを上書きする。

Turn判定:

```text
abs(cross) >= 0.24
dot >= -0.55
```

Visual distance:

```text
car   15 m
truck 21 m
bus   25 m
```

Incoming turn laneからoutgoing current lane centerへquadratic curveを構成する。

このmoduleはvehicle path、segT、edge occupancy、signalを変更しない。

## 9. Pedestrian crossing

### `PedestrianCrossingSafetyTuning`

Crossing candidateからroad node/axisを取り、crossing進入と横断中のconflict flagを維持する。

Vehicleがstop lineで正しく停止しているだけではpedestrian entryをdeadlockさせないよう、実crosswalk/intersection conflict zoneだけをvehicle blockとする。

### `PedestrianSignalWaitTuning`

Older safety layerの6m stopを外側からwrapする。

Blocked crossing時:

```text
WAIT_DISTANCE = 1.15 m
```

まで自前で接近させる。

その後:

- `waiting=1`
- velocity=0
- path/pathCursor保持

signal green + vehicle conflict解消後、base walkStepへ戻る。

## 10. Bus network

### Base `BusSystem`

Baseは3 lines × 2 axesのgrid routeを生成する。

Stop spacingのbase logicはBusSystemが所有する。

### `ShortBusRouteTuning`

Constants:

```ts
MAX_ROUTE_METERS = 5_000;
TARGET_ROUTE_METERS = 4_600;
MIN_BASE_SEGMENTS = 4;
```

実距離はRoad A* node path + stop edge offsetから計算する。

Base routeはoutward stop列へ戻してから、短いout-and-back segmentへ分割する。

Segmentが5,000 mを超える場合は末尾stopを減らす。

Rebuild後:

- `bus.routes`を短距離routeで置換
- 各stopの`routes` membershipを再構築
- fleetをspawn

Fleet:

```ts
nBus = meters >= 3200 || stopSeq.length >= 7 ? 4 : 3;
```

### Feeder

Base `makeStationFeeder()`後に距離を再測定する。

5 km超ならstation stop以外を候補ごとに1つずつ除去し、最短になる構成を選びながら5 km以下へ詰める。

5 km以下へできなければrouteを破棄する。

## 11. Fleet depot compatibility

### `FleetDepotOperations`

Taxi build fleet後にvehicleをtaxi depotへ配置する。

Bus `spawnBusOnRoute`をwrapし、route vehicleをbus depot位置からspawnして最初のstopへdispatchする。

`ShortBusRouteTuning`は`spawnRouteFleet`を後から置換するが、内部で`spawnBusOnRoute`を呼ぶためdepot patchを維持する。

## 12. Taxi

### `TaxiSystem`

Fleet target:

```ts
target = min(
  availableVehicles,
  max(18, min(120, round(population / 800)))
);
```

Phase:

```text
idle
to-pickup
boarding
occupied
alighting
```

Constants:

```text
BOARDING_SECONDS = 4
ALIGHTING_SECONDS = 4
```

### `TaxiIntegration`

Taxi candidate trip:

```text
tripDistance >= 350 m
```

Resident probabilityはwealth、night、distance、walking fallback等から計算し上限0.52。Visitorはpurpose別probabilityを持つ。

Compatibility上、taxi waiting/onboard Agentはbase storeでWaitingBus/OnBusを再利用し、Dashboard snapshotではtaxi passengersをbus countから差し引く。

```text

```

## 16. Rail runtime

Rail関連は複数moduleのimport chainで最終動作が成立する。

重要不変条件:

1. consist positionは単一running distanceを基準にする。
2. dwell中のarrival lane/platformを瞬間変更しない。
3. physical signal visibilityとlogical block stateを混同しない。
4. siding rail/platform/train offsetを一致させる。
5. station platform/accessをrunning railと無関係な軌跡へ置かない。
6. deadheadをpassenger-facing departure boardへ出さない。

主要実効値:

```text
timetable quantum: 15 s
terminal platform min: 270 m
siding offset: 10.4 m
```

## 17. A* / Worker / Performance

A*:

- touch nodeだけreset
- static graph route LRU cache
- route cache keyはnumeric

Road graphをruntime変更する場合はcache整合性を確認する。

Worker:

- SharedArrayBuffer対応時はshared state
- Pedestrian/Agent/POI worker pools

Rendering:

- GPU Instancing
- LOD
- filter時の一部sync skip
