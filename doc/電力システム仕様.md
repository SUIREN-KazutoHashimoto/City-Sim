# Machi-Sim 電力システム仕様

> Target: `develop` / synchronized at v1.0.30 / 2026-08-27. **最終的な正は現行ソースコード。**

## 1. 位置付け

本書は`src/power/`、電力施設generation/binding、ライフライン勤務、燃料物流、関連UIの現行仕様をまとめる。

旧Phase管理ではP1〜P10/P12を実装し、P11は電力オーバーレイ案だった。現在、未実装オーバーレイは電力限定Phaseとしてではなく、交通・電力から始める共通都市診断Overlayとして`../ROADMAP.md`へ統合している。

## 2. 全体構成

主な実装:

- `PowerSystem.ts`: 発電、外部受電、地下系統、変電所、需要家、Zone、dispatch、snapshot

- `GenerationFuelModel.ts`: thermal inventory、reorder、reserved inbound、消費
- `LifelineSupplyIntegration.ts`: 実Fuel Truck物流
- `PowerOperationalIntegration.ts`: 生産/商業/照明/rail等への影響
- `PowerPerformanceTuning.ts`: topology/consumer/path cache、性能計測
- `LifelineWorkforce.ts`: 電力を含む共通ライフライン職場registry
- `PowerFacilityGeneration.ts`: 電力施設を通常Buildingとして都市生成
- `PowerFacilityBuildingBinding.ts`: logical asset ↔ Building binding
- `PowerFacilityBuildingVisualTuning.ts`: Buildingへrole別detailを付加

- `PowerUiTuning.ts`: F10 power tab / Building power annotation
- `FullScreenMenuAnalyticsTuning.ts`: power metrics/history chart

## 3. 単位・state

内部電力は原則kW、UI/集計はMW。`1 MW = 1000 kW`。

Grid state:

- `normal`
- `tight`
- `limited-supply`
- `blackout`

Consumer state:

- `supplied`
- `limited`
- `blackout`
- `disconnected`

Asset state:

- `online`
- `standby`
- `offline`
- `fault`

Line state:

- `active`
- `broken`

## 4. 標準電源構成

標準`city.json`:

- Thermal: 2 × 350 MW
- Solar: 3 × 90 MW
- External: 2 × 600 MW
- Substation spacing: 1,800 m
- Substation rating: 75 MW
- Service radius: 2,600 m
- Source feeder rating floor: 600 MW

Solar available outputはsimulation時刻で変動する。

Generation dispatchは市内発電を優先し、不足分をexternal importで補う。したがって、健全な1 Zoneでexternal importが大きい場合、internal available generationが需要へ届いていない重要な診断信号になる。

## 5. 電力施設は通常Building

発電所・変電所・外部受電所はPowerSystem内だけの浮遊座標ではない。

`PowerFacilityGeneration`がCityGeneratorの生成済みBuildingから候補を選び、通常の都市生成中にpower facilityへ用途転換する。

候補選定は以下を避ける。

- 学校/病院等の既存special facility
- farm/raw-factory/processor/assembler等のproduction Building
- taxi/bus/freight depot
- 既に他infrastructureへ予約されたBuilding
- Park district

Role別にIndustrial/Logistics、Factory/Warehouse、低層、gate距離、target position、site area等をscoreして選ぶ。

選ばれたBuilding:

- Building IDを維持
- Parcel/frontageを維持
- categoryをWorkへ変更
- roleに応じてarchetype/roof/floorsを正規化
- 元POIをdisable
- 同じbuildingIdで専用Work POIを登録
- `infrastructureLabel`, `powerFacilityKey`, `powerFacilityRole`を付与
- frontage側nearest road nodeをaccess/electrical nodeとして記録

このため勤務先、Fuel Truck配送先、Inspector、Raycast、LOD、power UI jump、地上描画が同じ実Buildingを指す。

## 6. 地上描画・地下配線

通常表示で電線・電柱・架空線は描画しない。RoadNetwork Edgeを地下line topologyとして利用する。

一方、施設本体は地上Buildingとして描画する。

- Thermal: 通常Building + thermal color + stacks
- Solar: 通常Building + solar color + panel rows
- Substation: 通常Building + transformer/switchgear
- External: 通常Building + receiving/switchgear detail

独立したsecond facility meshを別座標へ配置しない。

## 7. ライフライン職場

`LifelineWorkforce`は将来の水道/下水/通信/ガス/緊急サービス等でも使える共通registry。

Generation facility Work POIは通常Agent workforceへ参加するが、欠員補完は通常職場より優先する。

### 7.1 Roster semantics

現行仕様では、**facility Work POI capacity = roster target**。

Rosterを3shift分に3倍しない。3交代は同一rosterをscheduleする。

標準:

```text
lifelineOnDutyRatio = 0.30
```

したがって、rosterの30%がon-dutyなら100% staffing capability。

Generation roster capacityの基礎:

```text
Thermal: max(8, ceil(maxMW / 100 × 4.5))
Solar:   max(2, ceil(maxMW / 100 × 1.5))
```

350 MW thermalは標準でroster 16、100%運転の同時targetは約5人。

### 7.2 Three shifts

```text
06:00–14:00
14:00–22:00
22:00–06:00
```

### 7.3 present / onDuty

`present`はscheduled + `AgentState.Engaged` + `goalPOI === work`の瞬間的な物理presence。

Lifeline operationには`onDuty`を使う。

- scheduled workerがそのshift中に実際にWork POIへ到着するとcheck-in
- 同じshiftでは食事/短い休憩でPOIを離れてもonDutyを維持
- 次shiftへは持ち越さない
- 別Work POIへは持ち越さない
- no-showはgrace終了後にonDutyへ数えない

Grace:

- shift handover: 45 simulation min
- attendance runtime startup: 60 simulation min

この設計により、少人数の発電所で1人が食事へ出た瞬間に大容量発電が20%単位で落ちる挙動を防ぐ。

## 8. 発電能力

Generation available output:

```text
base available output
× staffingFactor
× fuelFactor (thermal only)
```

`staffingFactor = clamp(onDuty / concurrentStaffTarget, 0, 1)`。

Startup前の未初期化attendanceは安全側でfactor 1として扱う。

## 9. Thermal fuel inventory

Thermal plantは抽象`thermal-fuel` inventoryを持つ。

標準:

- use: 0.18 units/MWh
- storage: max output換算96 h
- initial: 80%
- reorder: remaining 60 h
- emergency: remaining 18 h
- fuel truck capacity: 180 units
- fuel fleet: 10
- internal raw-factory reserve: 25%

Fuelはactual generationから消費する。

Fuel availability factorは次のdispatch intervalを賄えるstockがある間は1。Stockがほぼ空の時だけ利用可能割合へ低下し、0でgeneration capability 0。

## 10. Fuel procurement / truck flow

Reorder判定は`stock + reservedInbound`を使う。

Priority:

1. emergency/empty plant
2. remaining hoursが短いplant

Internal procurement:

```text
freight depot
→ raw-factory
→ loading
→ thermal plant
→ unloading
→ freight depot
```

Raw-factoryは`thermalFuelInternalReserveRatio`分を自分用に残す。

不足時のexternal import:

```text
freight depot
→ city gate
→ loading
→ thermal plant
→ unloading
→ freight depot
```

いずれも数値を直接plantへ足さず、Fuel Truckのunload完了時にstockへ反映する。

## 11. Underground network / rating

Road Edgeごとのbase rating:

| Road | rating |
|---|---:|
| Highway | 260 MW |
| Arterial | 180 MW |
| Collector | 110 MW |
| Local | 55 MW |
| Path | 12 MW |

`PowerGridCapacityTuning`はsource feeder path、station接続、consumer distribution pathに必要なrating floorを適用する。各updateでbaseを復元してから再計算し、古いupgradeを永久蓄積しない。

## 12. Power Zone

Power Zoneは電気的に接続されたcomponent/islandであり、substation service areaではない。健全に連系された都市は通常1 Zoneになり得る。

Zoneは利用可能なgeneration/import capacityを持ち、consumer allocationのhard供給上限になる。

## 13. 配電: hard constraintとsoft rating

現行`PowerDeliveryTuning`では以下をhard constraintとする。

- consumerにvalid substationがある
- substationがonlineでsourceを持つ
- consumer/substationがsame Zone
- source + distribution pathの全lineがactive
- Zoneにremaining source capacityがある

Consumerはpriority順で処理する。

```text
Critical → High → Medium → Low
```

Deliverable:

```text
min(consumer demand, zone remaining capacity)
```

Healthy line/substation ratingはinstantaneous hard load-shedding capには使わない。Flow allocation後にactual load/demandがratingを超えているかを判定し、`overload=true`を記録する。

目的は、接続Zoneに十分なsource capacityがあるのにline ratingで毎tick大量需要を切り捨てる人工的blackoutを避けること。将来はoverload duration/thermal accumulation/protection tripを別modelとして実装できる。

## 14. 優先給電・非常電源

Priority:

1. Critical: hospital, police, fire, road/rail signal等
2. High: station, school/university, public facility, rail operation等
3. Medium: factory, logistics, commercial, office, hotel等
4. Low: residential, street light等

Critical loadは標準35% emergency supply枠を持つ。

## 15. Demand model

基本:

```text
demand = base demand × building scale × activity × time factor
```

Residential、office、commercial、factory、logistics、hotel、hospital、education/public等を用途別に扱う。POI capacity/occupancyも反映する。

Non-Building loadとしてroad signal、street light、rail signal、station、rail tractionを持つ。

標準update:

- distribution/update: 5 simulation sec
- demand recalc: 15 simulation sec

## 16. Power quality

Nominal:

- 50 Hz
- 22 kV grid
- 400 V service

厳密Newton-Raphson AC power flowではなく大規模都市向けlinearized approximation。

- active P / reactive Q / apparent S / PF
- `Q = P × tan(acos(PF))`
- three-phase baseline A=0°, B=-120°, C=+120°
- per-phase current/voltage
- line R/X based voltage/phase drop approximation
- supply deficit based frequency droop
- phase imbalance

Standard line constants: R=0.18 Ω/km、X=0.11 Ω/km。

## 17. Simulation effects

Power supply/qualityは以下へ影響する。

- physical production/logistics efficiency
- office/commercial operating capability
- night building/street/station lighting
- rail traction under severe degradation
- signal operation through priority/emergency policy

Generation側もstaffing/fuelに依存するため、workforce shortage、traffic/logistics failureがsupply shortageへ波及する。

## 18. F10 Power UI

Power tab:

- grid state
- demand / supply
- city generation / external import
- available headroom
- blackout/limited/disconnected count
- frequency / voltage / reactive / PF / apparent power / imbalance
- generation/external facilities
- substations
- Power Zones
- overloaded/broken lines

`FullScreenMenuAnalyticsTuning`は従来の`reserve`表示を読みやすく補足し:

- city generation available/headroom
- external import max/headroom
- generation onDuty/target
- thermal fuel ratio

を表示する。

Power history:

- sample interval: 60 simulation sec
- max samples: 120
- series: demand, supply, city generation, external import

「予備力」はinternalだけの発電余力ではなく、利用可能なinternal generation + external max importに基づくsystem headroom。このためUIではcity/external headroomを分けて表示する。

## 19. Power facility Inspector / jump

Building Inspectorはpower facility `infrastructureLabel`とroleを表示する。

```text

```
