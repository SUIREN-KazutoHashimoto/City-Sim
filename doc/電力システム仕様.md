# City-Sim 電力システム仕様

## 1. 位置付け

対象: v1.0.12。最終的な正は現行ソースコード。本書は `src/power/` と関連runtime tuningの現行仕様をまとめる。

実装済み: Phase 1〜10、Phase 12。Phase 11（電力オーバーレイ）は未実装。

## 2. 全体構成

`PowerSystem` が発電、外部受電、地下電力線、変電所、建物/インフラ負荷、優先給電、停電を管理する。道路Edgeを地下電力線の論理経路として再利用し、通常時は電力線を描画しない。

主な実装:

- `PowerSystem.ts`: 系統構築、需給、配電、停電、snapshot
- `PowerTypes.ts`: 型、状態、設定、単位
- `PowerDemandModel.ts`: 建物/POI需要
- `PowerQualityModel.ts`: P/Q、電圧、周波数、位相、三相近似
- `PowerIntegration.ts`: World統合
- `PowerOperationalIntegration.ts`: 生産/交通/照明等への影響
- `PowerPerformanceTuning.ts`: キャッシュ、需要周期、性能計測
- `PowerRuntimeRegistry.ts`: runtime参照
- `PowerUiTuning.ts`: F10電力UI、Inspector拡張

## 3. 単位と状態

内部電力は原則kW、UI/集計はMWを使用する。`1 MW = 1000 kW`。

系統状態:

- `normal`: 正常
- `tight`: 逼迫
- `limited-supply`: 制限給電
- `blackout`: 停電

需要家状態は `supplied / limited / blackout / disconnected`。設備は `online / standby / offline / fault`、線路は `active / broken`。

## 4. 発電・外部受電

標準設定は火力2基×350 MW、太陽光3基×90 MW、外部系統2接続×600 MW。太陽光は時刻で出力が変動する。発電所と外部接続点は最寄り道路ノードへ接続される。

## 5. 地下電力網・変電所

道路Edgeを `PowerLineSegment` に対応させる。区間ごとに容量、現在負荷、有効/断線、過負荷、Power Zoneを保持する。

標準線路容量:

| 道路 | 容量 |
|---|---:|
| Highway | 260 MW |
| Arterial | 180 MW |
| Collector | 110 MW |
| Local | 55 MW |
| Path | 12 MW |

変電所は標準1,800 m間隔、75 MW/基、サービス半径2,600 m。発電源→変電所→需要家の到達性と経路容量を評価する。断線等でtopologyが変化した場合だけ再構築する。

## 6. 建物・インフラ接続

建物IDは変更せずside dataとして電力接続を保持する。主な値は需要、給電量、給電率、接続変電所、優先度、状態、Power Zone、配電経路。

非建物負荷として道路信号、街灯、鉄道信号、駅、鉄道牽引を扱う。

## 7. 需要モデル

基本形:

```text
需要 = 基本需要 × 建物規模 × 稼働率 × 時間帯係数
```

住宅、オフィス、商業、工場、物流、ホテル、病院、大学/学校、公共施設を用途別に扱い、POI capacity/occupancyも反映する。通常の系統更新は5 simulation秒、需要再計算は標準15 simulation秒。

## 8. 系統計算と局所不足

Power Zone単位で発電/外部受電、需要、供給、予備力を集計する。供給可能量はゾーン電源容量、変電所容量、共有幹線容量、需要家までの経路容量に制約される。

このため都市全体に余力があっても、断線、変電所容量超過、地域幹線過負荷により局所的な制限給電/停電が発生する。

## 9. 優先給電・非常電源

優先順位:

1. Critical: 病院、警察、消防、道路信号、鉄道信号
2. High: 駅、学校/大学、公共施設、鉄道運行
3. Medium: 工場、物流、商業、オフィス、ホテル等
4. Low: 住宅、街灯等

不足時は上位から容量を割り当てる。給電率は0〜1で保持する。Critical負荷には標準35%の非常電源枠を持たせ、信号系は停電が交通デッドロックを直接誘発しにくい安全側の挙動とする。

## 10. 電力品質モデル

50 Hz、22 kV系統、400 V需要家を標準とする。これは厳密なNewton-Raphson AC潮流ではなく、大規模都市向けの線形化近似モデル。

- 有効電力P、無効電力Q、皮相電力S、力率を扱う
- `Q = P × tan(acos(PF))`
- 三相基準位相: A=0°、B=-120°、C=+120°
- 大規模負荷はABC、小規模負荷はA/B/Cへ分散
- 相別電流、電圧、相不平衡率を計算
- 線路長とR/Xから電圧降下・位相差を近似
- 需給不足からdroop近似で周波数偏差を算出

標準線路定数は R=0.18 Ω/km、X=0.11 Ω/km。

## 11. シミュレーションへの影響

給電率と電力品質は工場/物流の生産、オフィス等の稼働、商業POIの実効能力、夜間建物照明、街灯、駅照明へ反映する。鉄道は軽微な不足では維持し、牽引電力品質が深刻に低下した場合のみ速度制限する。信号は優先給電/非常電源で可能な限り維持する。

## 12. UI

F10全画面メニューに「電力」を追加済み。都市全体の需要、供給、市内発電、外部受電、予備力/予備率、状態、停電数に加え、発電所、変電所、Power Zone、過負荷/断線区間を確認できる。

建物Inspectorでは需要、給電量、給電率、接続変電所、優先度、状態、電圧、周波数、力率、相を表示する。

Phase 11の地下幹線/停電地域オーバーレイは未実装であり、通常時の追加描画負荷はない。

## 13. 性能・安定性

- topology変更時のみ系統再構築
- Consumer一覧をキャッシュ
- 結合済み送電経路をキャッシュ
- 需要計算を配電更新から分離
- `powerPerformanceSnapshot()` で更新/配電/需要/topology時間と回数を取得
- CIで102,000 Consumer相当のストレスベンチを実行
- 断線→復旧、発電不足→正常復帰、seed差分を自動検証

P12導入時のCI synthetic benchmarkでは対象ホットパスが271.86 ms→137.43 ms（約1.98倍）だった。これはゲーム全体FPSの倍率ではない。

## 14. 主なSnapshot/API

- `powerSnapshot()`
- 発電所/外部受電/変電所/線路/建物/インフラ各snapshot
- Power Zone snapshot
- `powerQualitySnapshot()` と電気量snapshot
- `powerPerformanceSnapshot()`
- 建物需要override API
- 線路/発電所/外部接続/変電所の状態変更API

## 15. 未実装・非対象

未実装: Phase 11電力オーバーレイ。

現行近似モデルで扱わないもの: 厳密AC潮流、詳細なケーブル電気特性、厳密な送電損失、電気料金/電力市場。電柱、架空線、通常時の電線レンダリングも実装しない。

## 16. 変更時チェック

電力ロジック変更時は本書、`現行仕様書.md`、必要に応じて`基本設計書.md`/`詳細設計書.md`を更新する。`power`設定変更時は`設定ファイル仕様.md`も同期し、性能挙動変更時はP12 benchmarkとCIを確認する。
