# 性能モニタ仕様

## 1. 目的
100km²・数万人規模で、処理落ちの原因をレンダリングとシミュレーションの双方からリアルタイムに切り分ける。

## 2. 表示
画面右側に PERFORMANCE パネルを表示する。Pキーで表示/非表示を切り替える。
サンプリング間隔は250ms、履歴は最大240点（約60秒）。

### Frame timing
- Frame: requestAnimationFrame間隔
- Render: LOD更新、Agent/Vehicle/Signal同期、環境・照明更新、WebGLコマンド発行のCPU時間
- GPU: EXT_disjoint_timer_query_webgl2が利用可能な場合のGPU実行時間
- SIM: World.stepBatchAsyncのwall time
- 16.67ms / 33.33msの目安線を表示

### Rendering内訳
- LOD
- Agent sync
- Vehicle sync
- Signal sync
- Lighting / Environment
- WebGL submit

### Simulation内訳
積み上げグラフは重複しないトップレベル時間を表示する。
- Workers: Agent Worker + POI Search Worker。Ped WorkerはPed内のネスト時間として扱う
- Agent: Needs（同期fallback時）+ Utility判断 + trip開始/モード選択 + routing呼出し
- Ped: pedestrian block構築 + 歩行準備 + Ped Workerのspatial index / avoidance / movement
- Traffic
- Bus（update + onboard同期）
- Logistics
- Signals
- Activity: 車両到着処理 + Engaged活動/退出確定
- Other: batch総時間から上記を引いた残余

### Ped詳細
Pedは以下を個別表示する。
- Block: 横断歩道付近のpedestrian block / vehicle block構築
- Index: 同期fallback時のみ使用する従来SpatialHashGrid再構築。Worker利用時はほぼ0になる
- Walk/AvoidPrep: 表示名は互換のため残すが、第2段階以降は主に目標ノード、信号待ち、到着判定、base desired vector生成
- WorkerMove: 表示名は互換のため残すが、第2段階以降は Worker spatial index構築 + separation/avoidance + 速度/位置/向き/energy更新の合計wall time

Pedestrian WorkerはSharedArrayBuffer上のAgent SoAを直接更新する。Coordinatorは経路カーソル、信号、バス/車への乗り換え、POI到着など状態遷移だけを担当する。
Worker側は各stepの開始時点の歩行者座標をsnapshotへコピーし、そのsnapshotからlinked-cell spatial indexを構築する。その後、複数Workerが同じsnapshotを読みながら近傍分離・回避と移動積分を並列実行するため、別Workerがlive座標を書き換えても同一step内の近傍判定は変化しない。

Spatial indexのセルサイズは8m。10km級市街地でも全セルを毎step初期化せず、前stepで使用したセルだけをクリアするsparse clear方式とする。

横断歩道Block判定では、従来毎step `SidewalkNetwork.edgeBetween()` を全歩行者に対して実行していたが、現在のpath cursorに対応する「次の横断road node / axis」を経路設定・cursor更新時にキャッシュし、step中はキャッシュ値だけを見る。

### POI詳細
POIは以下を個別表示する。
- WorkerSearch: POI Search Worker Poolのbatch wall time
- MainSearch: Coordinator側で実行されたfindBestの合計ms / 件数
- Parking: findNearestFreeの合計ms / 件数
- Reserve/Release: occupancy変更処理の合計ms / 件数
- Activity+Arrival: 施設滞在・退出、車両到着後処理

POI検索の静的データはWorkerへ複製し、occupancyのみSharedArrayBufferで共有する。reserve/releaseは競合回避のためCoordinator側で確定する。
Shared occupancyの更新はAtomics.store、Workerからの読み出しはAtomics.loadを使用する。

### A*診断
A*は親フェーズ内に含まれるため積み上げには二重計上しない。別途、以下を表示する。
- Walk A*: 合計ms / 件数 / 最大1件ms
- Vehicle A*: 合計ms / 件数 / 最大1件ms

## 3. Workload
- LOD0/1のVisible Agent数
- LOD0/1のVisible Vehicle数
- 移動中/バス待ちの歩行者数
- Driving状態の車両数
- 建物LOD0/1/2/3件数
- Simulation backlog

処理時間だけでなく処理件数を併記し、単純なオブジェクト増加と1件あたり処理コストの悪化を切り分ける。

## 4. POI検索最適化
POIRegistryはカテゴリ別SpatialHashGridを使用する。
従来の拡大検索では300→800→2000mの各段階で内側セルを再走査していたため、queryExpandingを追加し、前段で走査済みのセルを除外して外周セルだけを追加走査する。

RuntimeのUtilityBrainは、行動カテゴリ決定と施設検索を分離する。
Home/Workのような直接目的地はCoordinatorで即時確定し、Food/Retail/Leisure等の検索が必要なAgentだけを最大512件単位でPOI Search Worker Poolへまとめて送る。

Workerが返した候補は最終確定ではない。beginTrip時にCoordinatorがreserve可否を再確認し、満員の場合は既存fallback検索を行う。

## 5. 計測負荷への配慮
Agentや歩行者を1個体ごとにperformance.now()で計測しない。
World.stepCore / stepCoreAsyncのフェーズ境界をラップして一括計測する。
POIのfindBest/findNearestFree/reserve/releaseは呼出単位で集計するが、個体全処理を分解する計測は行わない。
A*のみ経路探索リクエスト単位で計測する。
PerformanceパネルのCanvas再描画は4Hzに抑える。

## 6. 注意事項
GPU時間はWebGL2のEXT_disjoint_timer_query_webgl2が利用できない環境ではn/aとなる。
SIM内のA*値とPOI MainSearch/Parking/Reserve値、Ped WorkerMoveは親フェーズにも含まれるネスト計測であり、積み上げSIM時間へ追加してはならない。
POI Worker / Pedestrian WorkerはSharedArrayBufferが利用できない場合は無効化され、同期処理へfallbackする。
同期 `World.step()` では従来のMain Thread SpatialHashGridを利用し、非同期 `stepBatchAsync()` のPed Worker経路だけWorker spatial indexへ切り替える。
