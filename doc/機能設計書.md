## 3. F-01 設定読込

### 入力

`public/config/city.json`

### 処理

- JSON取得
- default merge
- 値域検証
- `seed="random"` 解決

### 出力

`RuntimeCityConfig`

### 制約

設定値とruntime実効値を区別する。`railStationSpacing`は固定駅間隔、`parkRatio`は最終公園率ではない。

## 4. F-02 simulation time

SimulationClockがreal timeとsimulation timeを分離する。PreRoll中も通常simulation pathを使う。

高倍率時はbatch/backlog制御を行い、Railは独自frame budgetを持つ。

## 5. F-03/F-04 都市生成

### 入力

Planning options、Seed、都市サイズ。

### 処理

```text
Planning
→ Road hierarchy
→ Block/Parcel
→ Building/POI
→ special/rural facilities
→ final refinement
```

公園は高さ帯別quotaで余剰をtrimする。駅周辺は物理rail clearanceと最終no-building clearanceを持つ。

### 出力

RoadNetwork、Building、POI、Park/Facility metadata。

## 6. F-05 農場・郊外産業・Fleet depot

Farmはfield + office + warehouseのmulti-block estate。Field extentと物流sourceを分離する。

Taxi / Bus / Freight depotは専用Building・road access・private parkingを持つ。

Production chain:

```text
farm/raw-factory → processor → assembler → retail/food or export
```

## 7. F-06 電力施設Building生成

### 入力

生成済みBuilding、District、RoadNetwork、PowerConfig。

### 処理

- 特殊施設、production site、fleet depot、既予約infrastructureを候補から除外
- 発電所はIndustrial/LogisticsのFactory/Warehouse系を優先
- substationは対象地域に近い低層・接道済みBuildingを優先
- external connectionはgate近傍のIndustrial/Logistics系を優先
- 選んだBuildingの既存POIを無効化し、Power用Work POIへ置換
- `powerFacilityKey/Role/Label` metadataを付与
- frontage側のroad nodeを接続nodeとして記録

### 出力

Power assetにbinding可能な`PlannedPowerFacilityBuilding`。

### 制約

独立した別施設mesh/別座標を生成しない。同じBuildingを勤務先・物流先・描画・Inspector・jumpの正とする。

## 8. F-07 市民・Utility AI

AgentStoreに住民状態を保持し、UtilityBrainが勤務、食事、買物、娯楽、帰宅等を評価する。POI capacity/在庫/属性を考慮して目的地を選ぶ。

移動手段は徒歩、自家用車、バス、タクシー、在来鉄道。

## 9. F-08 一般職場attendance

一般職場:

- `present`: scheduled + Engaged + assigned work一致
- `assigned`: workPOI割当人数
- `capacity`: Work POI定員

Production siteはWork POIをaggregateし、attendanceとpower factorからactual process rateを決める。

## 10. F-09 ライフライン勤務

### 入力

Lifeline workplace registry、Agent shift、Work POI attendance。

### 処理

- 3交代shiftへ割当
- ライフライン欠員を通常職場より優先して補完
- scheduled workerが実際にWork POIへ到着したらcurrent shiftへcheck-in
- checked-in workerは同一shift内の短い離席でも`onDuty`
- startup/handover graceを適用

### 出力

`present / onDuty / scheduled / assigned / capacity / efficiency`。

### 制約

- `lifelineOnDutyRatio=0.30`
- rosterを3倍しない
- 次shift/別workplaceへcheck-inを持ち越さない
- no-showはgrace後に能力低下へ反映

## 11. F-10 徒歩・横断歩道

Sidewalk A* routeを使用。赤信号でもrouteを破棄せずcrossing入口付近で待機する。横断中pedestrian occupancyはvehicle conflictへ反映する。

## 12. F-11 道路車両・多車線

RoadNetwork A* + TrafficSystemがlogical movementを担当する。

MultiLane runtimeはlane/target lane/lane change/turn laneを追加する。TurningLaneTransitionFixはturn laneとdownstream lane reductionの競合を解消し、TurningVisualPathTuningは表示poseだけを曲線補間する。

## 13. F-12 バス

ShortBusRouteTuningは実Road A*距離でcyclic routeを5 km以下へ再構成する。通常3～4台/route。Station feederも同じ距離上限を使う。

## 14. F-13 タクシー

Taxi phase:

```text
idle → to-pickup → boarding → occupied → alighting
```

住民/visitorのtrip距離・時間帯・属性等から選択する。Taxi-specific stateはside dataへ保持する。

## 15. F-14 一般産業物流

Truck phase:

```text
idle → toSource → loading → toDestination → unloading → returning
```

Production input/output inventoryを実車両で移送し、最終製品はRetail/Foodまたはgate exportへ送る。

## 16. F-15 発電所燃料物流

### 入力

火力fuel stock、reserved inbound、raw-factory余剰、city gate、VehicleStore/TrafficSystem。

### 処理

- reorder/emergency条件で補給要求
- raw-factoryの内部reserveを残し、市内余剰を優先
- 不足時は外部gateをsourceにする
- fuel truckが積込→plant→unload→depot return

### 出力

発電所在庫、reserved inbound、received internal/external totals。

### 制約

在庫はtruck unload完了時にのみ増える。

## 17. F-16 電力需給・配電

### 入力

Generation/external availability、consumer demand、topology、priority。

### 処理

1. topology/asset stateで接続可否を決定
2. priority順にZone supply capacityを割当
3. pathへactual flowを加算
4. line/substation rating超過をoverloadとして診断
5. emergency power適用
6. generation dispatch

### 制約

健全line/substation ratingは現在instant hard capではない。broken/disconnected、asset fault/offline、Zone source capacityがhard constraint。

## 18. F-17 電力品質・運用影響

P/Q/S、PF、voltage、frequency、phase imbalanceを近似計算する。Power operational factorをproduction、commercial capacity、lighting、rail等へ反映する。

## 19. F-18～F-20 鉄道

Planningは標準3幹線+副都心支線。Configured station spacingを中心→外縁で拡大する。

在来鉄道はLocal/Rapid/Limited、右側通行、block/signal、passing、terminal/depot、deadhead、15秒timetable quantum、physical passengersを持つ。

External high-speed railは別subsystemとして運行/旅客交換/Inspector snapshotを提供する。

## 20. F-21 描画

EnhancedRendererはBuilding/Agent/VehicleをGPU Instancing + LODで描画する。

Power facilitiesも通常Building pipelineを使用し、role別detailだけを追加する。電線・電柱は通常描画しない。

## 21. F-22 Inspector / follow / jump

Inspectorはfeature-specific runtime tuningで説明を追加する。

Jumpは実entityを解決してからメニューを正式に閉じ、camera/follow stateを更新する。Power assetはbindingの`buildingId`から実Buildingを解決する。

## 22. F-23 F10全画面メニュー

現行ページ:

- Buildings
- Cars
- Buses
- Taxis
- Trucks
- Trains
- Power
- Graphics

List pagesはsearch、paging/refresh、status/detail、jumpを持つ。

## 23. F-24 Analytics / graph

SVG/CSSの軽量chartを利用し、外部chart dependencyを追加しない。

- Building use / POI utilization
- Car state
- Bus operation / occupancy
- Taxi phase
- Truck kind/phase/load
- Train normalized state
- Power demand/supply/internal/external history and headroom

Power historyは1 simulation分間隔、最大120 samples。

## 24. F-25 Performance

SoA、SharedArrayBuffer/Worker、SpatialHash、A* cache、GPU instancing、LOD、power cache、simulation/render/rail予算を使う。

CIはbuild、power stress benchmark、legal-file verificationを行う。
