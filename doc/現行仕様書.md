# City-Sim 現行仕様書

> Target: `develop` / synchronized at v1.0.30 / 2026-08-27. **最終的な正は現行ソースコード。**

## 1. 位置付け

本書は、現在のdevelopで成立している外部挙動・主要制約を横断的に確認するための仕様スナップショットである。実装理由は`基本設計書.md`、機能単位の契約は`機能設計書.md`、patch順や内部定数は`詳細設計書.md`、将来計画は`../ROADMAP.md`を参照する。

## 2. 標準起動設定

`public/config/city.json` の主要値:

| 項目 | 値 |
|---|---:|
| Seed | `random` |
| 都市面積 | 100 km² |
| 都市一辺 | 10 km |
| 市街地目標比率 | 0.40 |
| 基準街区 | 90 m |
| 初期人口 | 50,000 |
| Agent capacity | 120,000 |
| Vehicle capacity | 30,000 |
| 副都心数 | 3 |
| Arterial間隔 | 900 m |
| Collector間隔 | 360 m |
| Industrial比率 | 0.08 |
| Park計画比率 | 0.055 |
| 幹線鉄道路線 | 3 |
| `railStationSpacing` | 525 m（基準値） |
| 駅影響半径 | 900 m |
| 電力更新 | 5 simulation秒 |
| 電力需要再計算 | 15 simulation秒 |

`railStationSpacing=525` は固定実距離ではなく、中心部でほぼ1.0倍、都市外縁ほど最大約2.0倍へ拡大する基準値。`parkRatio=0.055` は初期計画値であり、最終公園率を保証しない。

## 3. 起動・時間

1. `CityConfigLoader` が設定を取得・merge・検証する。
2. `CityGenerator` とgeneration tuning群が都市を生成・refineする。
3. `World` が市民・交通・物流・電力等を初期化する。
4. Loading中に通常simulationをpre-rollし、visible start直後の初期burstを平準化する。
5. three.js scene、rail、Inspector/UIを構築する。
6. simulationとrender frameは分離して進行する。

高倍率時はsimulationをbatch処理し、backlogに応じてrender cadenceを調整する。Railは独立したframe budget/backlogを持つ。

# 都市生成

## 4. 都市計画・道路・建物

主なDistrictはCBD、Commercial、MixedUse、ResidentialHigh/Low、Industrial、Logistics、Civic、Park。

道路階層:

```text
Highway > Arterial > Collector > Local > Path
```

標準ではCBD/CommercialのArterialは1方向3車線、その他Arterialは2車線。高密度Collectorは2車線化できる。Localは通常1車線で、低密度・郊外ほど一部を省略する。

道路で囲まれたBlockをParcelへ分割し、frontage、depth、setback、parcel統合、development intensity、coverage/FAR等からBuildingとPOIを生成する。

## 5. 公園・森林・駅周辺

公園は最終段で周辺高さ帯ごとの上限を目安に余剰を削る。

- 高層/超高層: 約2%
- 中層: 約1%
- 低層: 約5%

不足分を追加生成する処理ではない。

森林・街路樹は最終RoadNetworkとのclearanceを検査し、車道内に入る樹木を描画しない。

駅周辺は、線路/駅設備との物理包絡clearanceと、駅中心からの最終no-building clearanceを別に持つ。最終基本半径はCentral/SubCenter 78 m、Local/Terminal 56 mで、Building footprint半対角を加えて判定する。

## 6. 農場・産業・営業所

Taxi / Bus / Freightは専用depotを持ち、一般住民用Parkingとは分離する。

Farmはmulti-block estateとして扱う。

```text
大型field + office + warehouse
```

物流sourceはwarehouse側、畑面積・描画はfield extentを使う。Farmの100%時base productionはfield areaから決定する。

物理サプライチェーン:

```text
farm / raw-factory
      ↓
processor
      ↓
assembler
      ↓
Retail / Food または city gate export
```

一般物流truckはFreight depotをhomeとし、source移動、loading、destination移動、unloading、帰庫を実走行する。

# 市民・職場・交通

## 7. 市民・移動手段

Utility AIが勤務、食事、買物、娯楽、帰宅等を評価し、POI容量/在庫/属性を考慮して行動する。

主な移動手段:

- 徒歩
- 自家用車
- 路線バス
- タクシー
- 在来鉄道

## 8. 一般職場

一般Work POIは以下を区別する。

- `present`: 勤務時間中で、現在そのWork POIに`Engaged`している人数
- `assigned`: `workPOI`がその職場を指す在籍人数
- `capacity`: Work POI定員

生産拠点では、出勤状況と電力のoperational factorを実生産へ反映する。一般office/commercial等の稼働率は主に診断情報であり、完全な貨幣経済モデルは未実装。

## 9. ライフライン勤務

発電所は通常のAgent/Work POIを利用するライフライン職場として登録する。

3交代:

```text
06:00–14:00
14:00–22:00
22:00–06:00
```

**ロスターは施設の在籍定員そのもの**であり、3シフト分を機械的に3倍した人数ではない。`lifelineOnDutyRatio=0.30` のため、ロスターの30%がon-dutyなら100%のstaffing capabilityとする。

ライフラインでは、瞬間的な建物内人数`present`とは別に`onDuty`を持つ。予定シフト中に実際に職場へ到着したAgentを、その同一シフト中はチェックイン済みとして扱う。食事等の短い離席だけで運転能力を即時喪失しない。

- shift handover grace: 45 simulation分
- runtime startup grace: 60 simulation分
- 別職場/次シフトへcheck-inは持ち越さない
- grace終了後に一度もcheck-inしていないAgentはon-dutyに数えない

## 10. 道路交通・歩行者

Car / Truck / Bus / TaxiはRoadNetwork A* routeとTrafficSystemを使用する。TrafficSystemはEdge進行、signal、pedestrian conflict、occupancy、IDM系follow、arrivalを扱う。

MultiLane runtimeがlane選択、target lane、lane change、turn laneを追加する。交差点の表示軌道補正はsimulation pathとは分離する。

歩行者は赤信号時もSidewalk routeを破棄せず、crossing入口付近で停止し、青+安全になれば同routeを継続する。

## 11. バス・タクシー

一般バスは実Road A*距離で1 cyclic route 5,000 m以下を基本とし、通常3～4台/route。駅feederも同じ距離制約を受ける。

Taxiはidle / to-pickup / boarding / occupied / alightingを持ち、住民/来訪者の距離・時間帯・属性等で選択される。

# 電力

## 12. 標準電源構成

標準設定:

- thermal: 2基 × 350 MW
- solar: 3基 × 90 MW
- external connection: 2接続 × 600 MW
- substation: 1,800 m基準間隔、75 MW/基
- nominal: 50 Hz / 22 kV / 400 V service

太陽光は時刻で利用可能出力が変動する。発電dispatchは市内発電を優先し、不足分を外部受電で補う。

## 13. 電力施設の実体

発電所、変電所、外部受電所はPowerSystemだけの浮遊座標ではない。

`PowerFacilityGeneration` が通常都市生成で作られた接道済みBuildingを予約・用途転換し、同じBuilding ID、parcel/frontage、Work POI、Inspector、Raycast、LODを使用する。PowerSystemはbinding経由でそのBuilding位置とfrontage側road nodeを参照する。

通常表示:

- 電線・電柱: 地下埋設扱いで非表示
- 火力発電所: 通常Building + 発電所色/煙突
- 太陽光発電所: 通常Building + panel detail
- 変電所/外部受電所: 通常Building + transformer/switchgear detail

## 14. 地下電力網・配電

道路Edgeを地下`PowerLineSegment`の論理経路として再利用する。Power Zoneは電気的に接続された島/componentであり、変電所のservice areaそのものではない。健全に連系された都市は通常1 Zoneになり得る。

hard constraint:

- broken/disconnected topology
- offline/fault asset
- Zoneで利用可能な発電/外部受電容量

line/substation ratingは現在**soft overload diagnostic**。健全設備の定格を瞬間的な配電hard capには使わず、実flowがratingを超えた場合にoverload flagを立てる。時間依存のthermal trip/protectionは未実装。

## 15. 発電所人員・燃料

発電利用可能出力:

```text
base available output
× staffing factor
× fuel factor (thermal only)
```

staffing factorはライフライン`onDuty / concurrentStaffTarget`で評価する。

火力は抽象`thermal-fuel`在庫を持つ。

- consumption: 0.18 units/MWh
- storage: 最大出力換算96 h
- initial stock: 80%
- reorder: 残60 h
- emergency: 残18 h
- fuel truck: 180 units/台、最大10台
- internal raw-factory reserve: 25%

市内raw-factory余剰を優先し、不足時はcity gateから輸入する。どちらも実Truckが積込・道路走行・荷下ろしを完了して初めて発電所在庫へ加算する。

## 16. 需要・優先給電・品質

住宅、office、商業、工場、物流、hotel、病院、教育、公共施設等を用途別需要として扱う。信号、街灯、鉄道信号、駅、鉄道牽引も非Building負荷として持つ。

不足時はCritical → High → Medium → Lowの順で供給する。Critical負荷は非常電源枠を持つ。

電力品質は厳密AC潮流ではなく、大規模都市用の近似model。P/Q/S、PF、相別電流、電圧、周波数、相不平衡等を計算する。

# 鉄道

## 17. 在来鉄道・外部鉄道

標準3幹線+副都心支線。`railStationSpacing=525`はbaseで、郊外ほど最大約2倍へ拡大する。

運行はLocal/Rapid/Limited、右側通行、block/signal、passing、terminal/depot、deadhead、15秒timetable quantumを持つ。

旅客はstreet → station access → platform → 実停車列車 → platform → streetを物理移動し、最大1回transferをサポートする。

外部接続高速鉄道は別subsystemとして運行・旅客交換・Inspector/follow snapshotを持つ。

# 描画・UI

## 18. 描画

`EnhancedRenderer`はGPU Instancingと距離LODを使用する。都市Building、Agent、Vehicleの大規模描画を担当し、feature tuningが農地、森林、道路標示、taxi、power facility detail等を追加する。

## 19. Inspector

UniversalInspectorをbaseにfeature-specific情報を追加する。代表表示:

- Workplace: 種別、present/onDuty、assigned、capacity、efficiency
- Vehicle: lane、taxi/truck状態
- Power Building: 施設名、需要、供給率、接続変電所、品質
- Train/high-speed train: 運行/追跡情報

## 20. F10全画面メニュー

`F10`で開閉。シミュレーションは継続する。

現行の主なページ:

- 建物一覧
- 乗用車一覧
- バス一覧
- タクシー一覧
- トラック一覧
- 列車一覧
- 電力
- グラフィックス設定

一覧は検索・ページング・ジャンプを持つ。ジャンプは対象entity/Buildingを解決してからメニューを正式に閉じ、カメラを移動する。

### 20.1 Analytics

外部chart libraryを追加せずSVG/CSSで軽量描画する。

- 建物: 用途構成、POI利用
- 乗用車: vehicle state
- バス: 運行状態、乗車率
- タクシー: 営業phase
- トラック: 一般物流/燃料輸送、運行phase
- 列車: 現在ページの正規化した運行状態
- 電力: demand/supply/internal/external時系列、現在の供給余力

Power historyは1 simulation分間隔、最大120 samplesを保持する。

## 21. Performance

主な方針:

- SoA TypedArray
- SharedArrayBuffer / Worker
- SpatialHash
- A* cache
- GPU Instancing / LOD
- simulation/render/rail個別budget
- power topology/consumer/path cache

CIはTypeScript/Vite build、電力P12 stress benchmark、legal files検証を行う。

## 22. 未実装・将来計画

現行に含まれない主なもの:

- 都市診断OverlayManagerと交通/電力/人口等の3D overlay
- 厳密AC潮流
- 電力設備の時間依存thermal protection/trip
- 電気料金/電力市場
- 完全な貨幣/価格/利益経済

Overlayは旧「電力Phase 11だけ」の扱いではなく、交通・電力から始めて人口、公共交通、雇用、土地利用、物流、accessibility、developer diagnosticsへ拡張する共通基盤として`../ROADMAP.md`で管理する。
