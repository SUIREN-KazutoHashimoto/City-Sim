# City-Sim 現行仕様書

## 1. 文書の位置付け

- 対象: 現行実装（文書同期時点 `v0.1.41`）
- 更新基準日: 2026-08-25
- 目的: 現在コード上で成立している都市生成・交通・鉄道・旅客・描画・UI仕様を一冊で確認できるようにする。
- **最終的な正はソースコード**であり、本書はコードから作成した現行仕様スナップショットである。
- `CityGeneratorV2_Phase*.md` は履歴資料であり、現行仕様の根拠には使用しない。

## 2. 標準起動設定

`public/config/city.json` の生設定:

| 項目 | 値 |
|---|---:|
| Seed | `random` |
| 都市面積 | 100 km² |
| 都市一辺 | 10 km |
| 市街地目標比率 | 0.40 |
| 基準街区 | 90 m |
| 初期人口 | 50,000 |
| Agent capacity | 60,000 |
| Vehicle capacity | 30,000 |
| 副都心数 | 3 |
| Arterial間隔 | 900 m |
| Collector間隔 | 360 m |
| Industrial比率 | 0.08 |
| Park比率 | 0.055 |
| 鉄道 | 有効 |
| 幹線鉄道路線 | 3 |
| `railStationSpacing` | 525 m |
| 駅影響半径 | 900 m |
| 副都心支線 | 有効 |

### 2.1 駅間隔の実効値

`RailPlanningEnhancements.ts` には `DEFAULT_RAIL_PLANNING.railStationSpacing *= 1.5` が存在する。ただし通常起動では `CityConfigLoader` が `city.json` の明示値 `525` をplanning optionsへ入れ、`RailNetworkPlan` のoptions mergeでもその明示値がdefaultより優先される。

したがって、**現行の通常起動で使われる実効駅間隔基準は525 m**である。1.5倍の意図はコード上に残るが、通常設定経路には反映されていない。

## 3. 起動・シミュレーション時間

1. 設定を読込・検証し、Seedを解決する。
2. 都市を生成する。
3. Loading中に実シミュレーションを事前進行し、画面表示開始時点を08:00付近へ安定化する。
4. 静的描画、鉄道、動的Mesh、UIを構築する。
5. `requestAnimationFrame` とシミュレーションstepを分離して進行する。

高倍率時はWorld処理をbatch化し、lag/backlogがある場合は描画頻度を落とす。Railは `RailFrameScheduler` が別CPU予算で処理し、未処理秒を `RailBacklog` として次frameへ繰り越す。

## 4. 都市生成

### 4.1 都市計画

主なDistrict:

- CBD
- Commercial
- MixedUse
- ResidentialHigh
- ResidentialLow
- Industrial
- Logistics
- Civic
- Park

`urbanScore`、`landValue`、`density`、中心影響、駅影響を別値として扱う。

### 4.2 道路

```text
Highway > Arterial > Collector > Local > Path
```

RoadNetworkは都市計画、Block/Parcel、車両交通、鉄道最終線形の骨格となる。

### 4.3 Block / Parcel / 建物

街区をParcelへ分割し、frontage、depth、setback、駐車、parcel統合、開発強度、coverage/FAR等から建物を生成する。用途POIと建築アーキタイプは別概念とする。

### 4.4 特殊施設・公園

学校、病院、大学、市役所、警察、消防、商業施設、ホテル、ガソリンスタンド、スタジアム、公園等を生成する。

### 4.5 駅周辺クリアランス

駅周辺blockを丸ごと公園化する処理は現行では使用しない。

`RailStationClearance` は実際の線路包絡へ干渉する建物・駐車場だけを除去する。Central/SubCenter周辺の安全な一般建物は2～4階程度の低層中型商業へ再構成し、Food / Retail / 一部Leisure POIを持たせる。特殊施設建物はこの駅前商業化の対象外。

## 5. 市民・交通手段

現行 `AgentState` の主要移動状態:

```text
Idle / Routing / Traveling / Engaged
ToVehicle / Driving
ToBusStop / WaitingBus / OnBus
ToRailStation / WaitingTrain / OnTrain
```

利用手段:

- 徒歩
- 自家用車
- 路線バス
- 鉄道

Utility AIが勤務、食事、買物、娯楽、帰宅等を評価し、POI予約・在庫・容量と組み合わせて行動先を決める。

## 6. 道路車両

### 6.1 基本交通

自動車、トラック、バスはRoadNetwork上でA*経路を持ち、TrafficSystemがEdge占有、信号、前走車、歩行者block、IDM系追従を処理する。

### 6.2 交差点旋回

現行は「直線Edgeを瞬時に折れて向きだけ後追い補間」ではない。

`TrafficTurningTuning` が交差点手前～出口を三次Bezier曲線で接続し、位置とheadingを同じ曲線接線から算出する。

基準旋回半径:

- 乗用車: 10.5 m
- トラック: 15 m
- バス: 18 m

90度級の旋回速度目安:

- 乗用車: 約30 km/h
- トラック: 約24 km/h
- バス: 約22 km/h

旋回手前ではfree-road目標速度だけを一時制限し、信号・IDM・車間制御は既存TrafficSystemを維持する。表示用 `VehicleVisualSmoother` はsimulation stateを変更しない。

## 7. 在来鉄道計画

### 7.1 路線

標準構成は幹線3路線 + 必要に応じた副都心支線。

### 7.2 駅位置と線路位置

駅には複数の意味を持つ座標がある。

- `plannedX/Z`: TOD/計画上の駅位置
- `x/z`: 駅設備・アクセス文脈上の位置。Terminalや既存open spaceでは道路中心と一致しない場合がある
- `roadNode`: 道路ネットワーク上の接続点
- `line.path`: **実際の線路・列車走行の基準線**

`line.path` は可能な限り駅間の道路A* Node列から生成する。駅設備座標をline.pathへ挿入して線路を道路からS字に引き出すことはしない。

道路Nodeの削減はほぼ同一直線の点だけ。旧仕様の「幹線38 m / 支線28 m程度まで道路回廊から離れてChord化」は現行ではない。

90度を超える鋭角頂点だけ `RailCurveTuning` で複数点へ分割し、その後RailRendererの通常smooth処理を通す。

### 7.3 支線

支線は幹線駅から分岐する。

- 非終端の幹線駅を優先してjunctionを選ぶ
- 短すぎる候補は支線を作らず、近い幹線駅をSubCenterへ昇格
- 実際に支線を作る場合は junction + 中間駅 + SubCenter の最低3駅構成
- 支線pathを乗換駅へ強制投影して潰さない
- 支線列車は物理支線レールと同じ `trackOffsetAt(..., 0)` を使う

## 8. 在来鉄道運行

### 8.1 種別/編成

幹線:

- 普通: 4両
- 快速: 5両
- 特急: 5両

支線普通: 3両。

Fleetは駅数に応じて概ね Local 0.50n / Rapid 0.30n / Limited 0.10n、幹線では予備Localも持つ。

### 8.2 営業時間

- 営業開始: 05:00
- 最終出発基準: 23:30
- 朝ピーク: 07:00–09:30
- 夕ピーク: 17:00–19:30

### 8.3 15秒グリッドダイヤ

`RailTimetable`:

- pattern cycle: 180秒
- time quantum: 15秒

終端発車、通常旅客列車の予定到着/発車、通常dwellは15秒グリッドへquantizeする。発車案内板も秒まで表示する。

### 8.4 右側通行/閉塞

幹線複線の正規lane:

```text
進行 +1 → lane -1
進行 -1 → lane +1
```

各駅間は方向別3閉塞。信号は直後閉塞が不可なら赤、直後可/次不可なら黄、2閉塞先まで可なら緑。

停車中は到着laneを保持し、次進行方向のlane changeは発車route確定後に開始する。

### 8.5 待避線

最終実効待避線offsetは10.4 m。島式ホーム設計、物理siding rail、普通列車のsiding走行位置を同じ10.4 m profileへ揃える。

代表速度:

- turnout: 50 km/h
- siding: 70 km/h

駅進入ではturnout手前の残距離から許容速度を算出し、遠方から長時間低速になる挙動を抑える。

### 8.6 終端駅

終端ホームの有効長は最低270 m。終端は4線fanを持ち、dwell中は割当ホームを保持する。

### 8.7 車両基地・回送

営業時間外やretire対象列車は終端へ向かい、車両基地へ収容する。基地から出た列車も営業化するまで `deadhead` とする。

回送時:

- 中間駅には旅客停車しない
- endpointのみ停車対象
- 終端dwellは短縮
- Inspector表示は `回送` / `回送・信号待ち` / `回送・入庫待ち` 等
- 旅客向け発車案内板から除外

## 9. 鉄道旅客

鉄道はteleportではない。Agentは駅入口へ歩き、駅内3D routeでホームへ移動し、実際に停車中の対象列車へ乗る。

対応経路:

- 同一路線直通
- 最大1回乗換

乗換時は原則として地上へ戻らずホーム間接続を使う。複数階駅は隣接levelを順に接続し、道路上で階段を降ろさず道路外へ水平に逃がしてから地上へ降ろす。

簡易旅客定員は1両120人。Inspectorに乗客数/定員/混雑率を表示する。

## 10. 駅・ホーム

### 10.1 現行寸法

- ホーム上面: rail基準 +1.05 m
- slab厚: 0.56 m
- roof center: +4.45 m
- roof厚: 0.18 m
- terminal platform幅: 4.8 m
- terminal platform最小長: 270 m
- siding offset: 10.4 m

通常ホーム幅は旧baseより拡大しており、側式は+0.4 m、島式は+0.2 m相当。

### 10.2 線形

ホーム・屋根・壁・設備は最終smoothed lineへ追従する。緩いカーブは許容し、ホームだけを線路から切り離して完全直線にはしない。

### 10.3 外装/設備

旧platform/roof Meshは抑止し、現行Architectureがvisible slab/canopyを生成する。

設備:

- 柱
- 腰壁/ガラス/fascia
- ベンチ
- 自販機
- emissive蛍光灯
- platformごとの実 `PointLight`

駅内部はSolid Boxで埋めず、薄い外装部材で通行空間を残す。

### 10.4 発車案内板

小型の天井吊り下げ式。ホーム軸に対して垂直に設置する。

- 表示寸法: 約1.7 m × 0.55 m（frame約1.85 m × 0.68 m）
- 最大3列車
- `HH:MM:SS / 種別 / 行先`
- 15秒グリッド
- 状態: 接近 / 停車中 / 発車 / 待機
- `shouldStop()` を使い通過列車を除外
- 回送/depot列車を除外
- 島式ホームの左右番線は横並び配置

### 10.5 照明

蛍光灯Meshはemissive。さらに各platformへPointLightを持ち、夜・薄暮・昼でintensityを変更する。

在来列車は可視前照灯に加えて、最大12編成分をpoolするSpotLightで前方を実際に照らす。

## 11. 外部接続高速鉄道

外部高速鉄道は独立した実運行サブシステム。

代表値:

- 最高速度: 320 km/h
- headway: 15分
- 反対方向phase: 7分30秒
- 中央駅dwell: 12分
- 旅客定員: 1両90人

中央駅でVisitor系と乗降交換を行う。Inspectorから選択/追跡できる。

以前存在した「外部高速線の固定ステータスパネル」は通常UIから削除されており、追跡していない状態で常駐表示しない。

## 12. 描画フィルター

描画だけを切り替え、simulationは継続する。

個別カテゴリ:

- 地面
- 道路・信号・バス停
- 建物・公園・施設
- 線路・駅設備
- 列車
- 道路車両
- 歩行者

`列車` は在来線外装、前照灯/SpotLight、外部高速鉄道車両も含む。`線路・駅設備` と独立してON/OFF可能。

代表preset:

- 全表示
- 鉄道一式
- 線路のみ
- 列車のみ
- 道路のみ
- 鉄道+道路

非表示時もsimulationは止めない。一部dynamic visual syncは省略して検証負荷を軽減する。

## 13. UI / Inspector / Performance

### 13.1 管理ウィンドウ

次を共通window shellで管理する。

- 統計/FPS HUD
- 時間・速度Dashboard
- 描画フィルター
- Performance Monitor
- 追跡情報

共通仕様:

- title bar drag移動
- CSS resize
- clickで前面化
- 画面外へ出過ぎないclamp
- `×`で非表示
- position/size/visibilityをlocalStorage保存

初期状態は統計HUD・時間/速度を表示、描画フィルター・Performanceを非表示。追跡情報はInspectorがtracking中のときだけnative表示する。

### 13.2 GUI launcher

右下の小型 `UI` ボタンから各windowを表示/非表示できる。活動グラフのtoggleとwindow layout resetも提供する。

既存shortcut:

- `P`: Performance
- `F9`: 描画フィルター
- `G`: 活動グラフ

キー操作は補助であり、GUIだけでもwindow表示を管理できる。

### 13.3 Inspector

Agent、道路車両、在来列車、外部高速列車、建物、道路、信号、バス停、駅、駐車場、gate、park等をinspectできる。移動体は中クリックで追跡/解除。

## 14. Performance

主要方針:

- SoA TypedArray
- SharedArrayBuffer + Worker
- GPU Instancing
- LOD
- sparse/dirty clear
- spatial index
- A* touched-node初期化 + LRU route cache
- rail frame budget / backlog
- render/simulation breakdown計測

Performance Monitorは通常非表示で、GUIまたは`P`で表示する。詳細は `性能モニタ仕様.md`。

---

## 15. 既知の制約/技術的負債

- 鉄道旅客は最大1回乗換。
- 扉位置・ホーム群集流動は簡略化。
- RailRendererが運行と描画を同時に所有する。
- RailRenderer prototype patch chainが長くimport順依存。
- station geometry/accessはproceduralで、完全に一つの共有Station Modelには統合されていない。
- 外部高速鉄道は在来RailRendererとは別サブシステム。
- `railStationSpacing` の既定値×1.5処理は通常の明示configに上書きされ、実効525 mのまま。
- 静的都市はSeed再現を意図するが、全simulationの完全決定論は保証しない。
