# Machi-Sim 都市設定ファイル仕様

> Target: `develop` / synchronized at v1.0.30 / 2026-08-27. **現行コードと`public/config/city.json`を正とする。**

## 1. 目的

`public/config/city.json` の標準入力値と `CityConfigLoader` の意味を定義する。通常起動ではJSON値がcode defaultへ上書きされるため、実効標準値はJSONを確認する。

## 2. トップレベル

| 項目 | 標準JSON値 | 説明 |
|---|---:|---|
| `seed` | `random` | 都市Seed |
| `areaKm2` | 100 | 都市面積[km²] |
| `urbanRatioTarget` | 0.4 | 市街地目標比率 |
| `blockSize` | 90 | 基準街区[m] |
| `population` | 50000 | 初期人口 |
| `agentCapacity` | 120000 | AgentStore容量 |
| `vehicleCapacity` | 30000 | VehicleStore容量 |
| `planning` | object | 都市/鉄道計画 |
| `power` | object | 電力系統設定 |

`CityConfigLoader`のcode defaultでは`agentCapacity=60000`だが、標準`city.json`が120000を明示するため通常起動の実効値は120000。

## 3. planning

| 項目 | 標準値 |
|---|---:|
| `subCenters` | 3 |
| `arterialSpacing` | 900 |
| `collectorSpacing` | 360 |
| `industrialRatio` | 0.08 |
| `parkRatio` | 0.055 |
| `railEnabled` | true |
| `railTrunkLines` | 3 |
| `railStationSpacing` | 525 |
| `railInfluenceRadius` | 900 |
| `railSubCenterSpurs` | true |

`railStationSpacing`は固定実距離ではなく基準値で、runtimeで郊外ほど最大約2倍へ広がる。`parkRatio`は初期計画値で、最終公園量とは1対1対応しない。

## 4. power

### 4.1 基本系統

| 項目 | 標準値 | 説明 |
|---|---:|---|
| `enabled` | true | 電力システム有効 |
| `updateIntervalSec` | 5 | 配電更新周期[simulation sec] |
| `demandUpdateIntervalSec` | 15 | 需要再計算周期[simulation sec] |
| `thermalPlantCount` | 2 | 火力発電所数 |
| `thermalPlantCapacityMw` | 350 | 火力1基定格[MW] |
| `solarPlantCount` | 3 | 太陽光発電所数 |
| `solarPlantCapacityMw` | 90 | 太陽光1基定格[MW] |
| `externalConnectionCount` | 2 | 外部系統接続数 |
| `externalGridCapacityMw` | 600 | 外部接続1点上限[MW] |
| `substationSpacingMeters` | 1800 | 変電所配置基準間隔[m] |
| `substationCapacityMw` | 75 | 変電所nameplate rating[MW] |
| `substationServiceRadiusMeters` | 2600 | service radius[m] |
| `lineCapacityHighwayMw` | 260 | Highway地下線rating[MW] |
| `lineCapacityArterialMw` | 180 | Arterial地下線rating[MW] |
| `lineCapacityCollectorMw` | 110 | Collector地下線rating[MW] |
| `lineCapacityLocalMw` | 55 | Local地下線rating[MW] |
| `lineCapacityPathMw` | 12 | Path地下線rating[MW] |
| `sourceFeederCapacityMw` | 600 | source feeder rating floor[MW] |
| `tightReserveMarginRatio` | 0.15 | 逼迫判定の余力/需要閾値 |
| `blackoutSupplyRatio` | 0.05 | blackout判定供給率 |
| `criticalEmergencySupplyRatio` | 0.35 | Critical非常電源比率 |

Line/Substation ratingは現行`PowerDeliveryTuning`では健全設備の瞬間hard capではなくoverload diagnostic。Broken/offline/topologyとZone source capacityはhard constraint。

### 4.2 電力品質

| 項目 | 標準値 | 説明 |
|---|---:|---|
| `nominalFrequencyHz` | 50 | 公称周波数[Hz] |
| `nominalGridVoltageKv` | 22 | 系統公称電圧[kV] |
| `serviceVoltageV` | 400 | 需要家基準電圧[V] |
| `frequencyDroopRatio` | 0.04 | 周波数droop係数 |
| `voltageLoadDropPu` | 0.025 | 負荷由来電圧降下係数 |
| `reactiveVoltageDropPu` | 0.018 | 無効電力由来電圧降下係数 |
| `phaseImbalanceVoltageDropPu` | 0.035 | 相不平衡由来電圧降下係数 |
| `maxZonePhaseShiftDeg` | 6 | Zone最大位相偏移[deg] |
| `lineResistanceOhmPerKm` | 0.18 | 線路抵抗[Ω/km] |
| `lineReactanceOhmPerKm` | 0.11 | 線路リアクタンス[Ω/km] |

### 4.3 ライフライン人員

| 項目 | 標準値 | 説明 |
|---|---:|---|
| `lifelineOnDutyRatio` | 0.30 | ロスターに対し100%運転で必要な同時on-duty比率 |
| `thermalPlantStaffPer100Mw` | 4.5 | 火力のroster capacity算定[人/100 MW] |
| `solarPlantStaffPer100Mw` | 1.5 | 太陽光のroster capacity算定[人/100 MW] |

発電施設のroster targetは設備容量から算定したWork POI capacityであり、3交代だから3倍するモデルではない。同一rosterを3shiftへscheduleし、ロスターの30%がon-dutyなら100% staffing capabilityとする。

旧文書にあった`lifelineRosterReliefRatio`は現行`PowerConfig`には存在しないため使用しない。

### 4.4 火力燃料・輸送

| 項目 | 標準値 | 説明 |
|---|---:|---|
| `thermalFuelUnitsPerMwh` | 0.18 | 発電1 MWhあたりの抽象燃料消費 |
| `thermalFuelStorageHours` | 96 | 最大出力換算の貯蔵時間[h] |
| `thermalFuelReorderHours` | 60 | 補給要求開始残時間[h] |
| `thermalFuelEmergencyHours` | 18 | 緊急補給扱い開始残時間[h] |
| `thermalFuelTruckCapacityUnits` | 180 | 燃料輸送車1台積載量 |
| `thermalFuelFleetSize` | 10 | 燃料輸送fleet上限 |
| `thermalFuelInternalReserveRatio` | 0.25 | raw-factoryへ残す最低reserve比率 |

初期火力在庫はstorage capacityの80%。`stock + reservedInbound`がreorder point以下なら補給候補になる。市内raw-factory余剰を優先し、足りない場合はcity gateからimportする。どちらも実Truckのunload完了後に在庫へ加算する。

## 5. Loader値域

主な検証:

- `areaKm2`: 0.1..10000
- `population`: 1..1,000,000
- `agentCapacity`: population..1,500,000
- `vehicleCapacity`: 1..1,000,000
- `planning.subCenters`: 0..8
- `planning.railTrunkLines`: 1..3
- `planning.railStationSpacing`: 260..3000 m
- `power.updateIntervalSec`: 0.25..3600 sec
- `power.demandUpdateIntervalSec`: updateInterval..3600 sec
- generation/connection counts: fieldごとの整数範囲
- power capacities/ratings: 正値またはfieldごとの許容範囲
- `tightReserveMarginRatio`: 0..2
- `blackoutSupplyRatio`: 0..0.5
- `criticalEmergencySupplyRatio`: 0..1
- `nominalFrequencyHz`: 45..65
- `nominalGridVoltageKv`: 1..500
- `serviceVoltageV`: 100..1000
- `lifelineOnDutyRatio`: 0.05..1
- `thermalPlantStaffPer100Mw`, `solarPlantStaffPer100Mw`: 0.1..100
- `thermalFuelStorageHours`: 1..720
- `thermalFuelReorderHours`: 0..storage hours
- `thermalFuelEmergencyHours`: 0..reorder hours
- `thermalFuelInternalReserveRatio`: 0..0.95

## 6. Seed

`random`は起動時に乱数seedを解決する。数値指定は静的都市生成の再現に使えるが、動的simulation全体の完全決定論は保証しない。

Benchmark用query seed overrideはbenchmark holdが有効な場合だけ使用し、通常起動でstale queryが残った場合は除去する。

## 7. 設定変更時の同期

設定を変更した場合は最低限:

1. `public/config/city.json`
2. `src/config/CityConfigLoader.ts`
3. `PowerTypes.ts` / planning defaults（該当時）
4. 本書
5. `現行仕様書.md`
6. 分野別仕様書

を確認する。
