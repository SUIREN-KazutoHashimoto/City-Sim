# City-Sim 都市設定ファイル仕様

## 1. 目的

`public/config/city.json` は都市規模、人口、Store容量、都市計画・鉄道計画の**入力値**を定義する。

重要: JSON生設定とruntime patch後の実効挙動を区別する。最終的な正は現行コード。

- 文書同期時点: `v0.1.83`
- 更新基準日: 2026-08-26

## 2. 読込経路

```text
/config/city.json
  ↓
CityConfigLoader.loadCityConfig()
  ↓
DEFAULT_CONFIG + raw config
planning = DEFAULT_CITY_PLANNING + raw planning
  ↓
値域検証
  ↓
World / CityGenerator / CityPlanning
  ↓
runtime tuning
```

JSON取得失敗、型/値域不正は起動エラーとして扱う。

## 3. トップレベル

| 項目 | 型 | 現行生値 | 説明 |
|---|---|---:|---|
| `seed` | number / `"random"` | `random` | 都市Seed |
| `areaKm2` | number | 100 | 都市面積[km²] |
| `urbanRatioTarget` | number | 0.4 | 市街地目標比率 |
| `blockSize` | number | 90 | 基準街区[m] |
| `population` | integer | 50000 | 初期市民要求数 |
| `agentCapacity` | integer | 60000 | AgentStore容量 |
| `vehicleCapacity` | integer | 30000 | VehicleStore容量 |
| `planning` | object | - | 都市/鉄道計画入力 |

`sizeMeters = sqrt(areaKm2 * 1,000,000)`。現行100km²では10,000 m。

## 4. `planning`

| 項目 | 型 | 現行生値 | 説明 |
|---|---|---:|---|
| `subCenters` | integer | 3 | 副都心数 |
| `arterialSpacing` | number | 900 | Arterial基準間隔[m] |
| `collectorSpacing` | number | 360 | Collector基準間隔[m] |
| `industrialRatio` | number | 0.08 | 産業配置計画比率 |
| `parkRatio` | number | 0.055 | **初期Park計画用**比率 |
| `railEnabled` | boolean | true | 在来鉄道生成 |
| `railTrunkLines` | integer | 3 | 幹線数 |
| `railStationSpacing` | number | 525 | **駅間隔の基準値**[m] |
| `railInfluenceRadius` | number | 900 | TOD計画影響半径[m] |
| `railSubCenterSpurs` | boolean | true | 副都心支線生成 |

## 5. 現行JSON

```json
{
  "seed": "random",
  "areaKm2": 100,
  "urbanRatioTarget": 0.4,
  "blockSize": 90,
  "population": 50000,
  "agentCapacity": 60000,
  "vehicleCapacity": 30000,
  "planning": {
    "subCenters": 3,
    "arterialSpacing": 900,
    "collectorSpacing": 360,
    "industrialRatio": 0.08,
    "parkRatio": 0.055,
    "railEnabled": true,
    "railTrunkLines": 3,
    "railStationSpacing": 525,
    "railInfluenceRadius": 900,
    "railSubCenterSpurs": true
  }
}
```

## 6. 値域検証

`CityConfigLoader` の現行検証:

| 項目 | 範囲 |
|---|---|
| `areaKm2` | 0.1 .. 10,000 |
| `urbanRatioTarget` | 0.01 .. 0.95 |
| `blockSize` | 20 .. 500 m |
| `population` | 1 .. 1,000,000 |
| `agentCapacity` | population .. 1,500,000 |
| `vehicleCapacity` | 1 .. 1,000,000 |
| `subCenters` | 0 .. 8 |
| `arterialSpacing` | blockSize×3 .. 5000 |
| `collectorSpacing` | blockSize×2 .. arterialSpacing |
| `industrialRatio` | 0 .. 0.35 |
| `parkRatio` | 0 .. 0.25 |
| `railTrunkLines` | 1 .. 3 |
| `railStationSpacing` | 260 .. 3000 m |
| `railInfluenceRadius` | 300 .. 1800 m |

Boolean rail optionsは明示`false`のときだけfalseとして扱う。

## 7. Seed

### Random

```json
"seed": "random"
```

`crypto.getRandomValues()` が利用可能ならUint32 seedを生成する。利用不可時は時刻由来fallback。

### Fixed

```json
"seed": 123456789
```

Static generationの再現を意図する。ただし動的simulationの全てが完全決定論ではない。

## 8. `railStationSpacing` の実効仕様

旧文書では「JSON明示525がdefault tuningを上書きするため、実効も525 m」とだけ記載していたが、現行コードではそれだけでは不十分。

`525` は `RailNetworkPlan` が受け取る**base spacing**。

その後 `RailRuralStationSpacing` が場所ごとに:

```text
spacingAt = max(260, railStationSpacing * baseScale) × localityFactor
```

を使う。

`localityFactor` は:

```text
CBD付近 ≈ 1.0
都市外縁 ≈ 2.0
```

なので通常設定の幹線駅間隔基準は概ね525～1,050 mへ変化する。

SubCenter spurの途中駅は`baseScale=0.90`を使う。

したがって、設定ファイルの525 mを「全駅の固定実距離」として扱わない。

## 9. `parkRatio` の実効仕様

`parkRatio=0.055` はCityPlanning/Park tuningの**初期候補生成**へ影響する。

現行最終生成では `CityGenerationRefinement` が公園を高さ帯別quotaへtrimする。

```text
high/super-high: 約2%
mid:             約1%
low:             約5%
```

これは最終公園の上限目安であり、`parkRatio`と1対1対応しない。

公園の最終量を調整したい場合は、JSONだけでなくfinal park quota logicも確認する。

## 10. JSONにない現行主要定数

次は現在config化されておらず、コード側定数。

### Bus

```text
route max distance: 5000 m
route target:       4600 m
base minimum split: 4
fleet/route:        3 or 4
```

### Station final no-build clearance

```text
Central/SubCenter: 78 m + building half diagonal
Local/Terminal:    56 m + building half diagonal
```

### Farm production

```text
base process rate = max(6, fieldArea / 7000)
```

### Taxi fleet

```text
round(population / 800), clamp 18..120
```

これらをユーザー設定化する場合は、config schema、validator、本書、現行仕様書を同時更新する。

## 11. `railInfluenceRadius`

TOD/都市計画への駅影響半径。旅客の候補駅探索距離、駅no-build radius、物理platform長とは別値。

## 12. `railTrunkLines`

JSON生値3。Loader許容上限も3。通常実効3。

## 13. 性能への影響

特に負荷へ影響しやすい設定:

- `areaKm2`
- `population`
- `agentCapacity`
- `vehicleCapacity`
- `blockSize`
- `railStationSpacing`

加えて現行ではbus route数、taxi fleet、industrial truck fleet、production site数が派生的にvehicle loadへ影響する。

## 14. 設定変更時の更新対象

設定項目またはmerge方式を変更した場合:

1. `CityConfigLoader.ts` の型/検証
2. `public/config/city.json`
3. 本書
4. `現行仕様書.md`
5. 実効値がruntime tuningで変わる場合は `詳細設計書.md`
6. READMEに掲載している代表値

を同時に確認する。
