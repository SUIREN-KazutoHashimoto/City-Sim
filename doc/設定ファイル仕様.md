# City-Sim 都市設定ファイル仕様

## 1. 目的

都市生成条件、人口、Store容量、都市計画・鉄道計画パラメータをソースコードから分離する。

設定ファイル:

```text
public/config/city.json
```

ブラウザ起動時に `/config/city.json` から読み込む。

---

## 2. トップレベル設定

| 項目 | 型 | 説明 |
|---|---|---|
| `seed` | number / `"random"` | 都市生成Seed。`random` は起動ごとに実Seedを生成。 |
| `areaKm2` | number | 都市面積[km²]。正方形都市の一辺は `sqrt(areaKm2 * 1,000,000)` m。 |
| `urbanRatioTarget` | number | 市街地目標比率 0..1。 |
| `blockSize` | number | 基準街区サイズ[m]。 |
| `population` | integer | 初期市民要求数。 |
| `agentCapacity` | integer | AgentStore容量。population以上を推奨。 |
| `vehicleCapacity` | integer | VehicleStore容量。 |
| `planning` | object | 都市計画/鉄道計画設定。 |

---

## 3. `planning` 設定

| 項目 | 型 | 現行値 | 説明 |
|---|---|---:|---|
| `subCenters` | integer | 3 | 副都心数。 |
| `arterialSpacing` | number | 900 | Arterial基準間隔[m]。 |
| `collectorSpacing` | number | 360 | Collector基準間隔[m]。 |
| `industrialRatio` | number | 0.08 | 産業系配置比率の計画値。 |
| `parkRatio` | number | 0.055 | 公園配置比率の計画値。 |
| `railEnabled` | boolean | true | 鉄道生成を有効化。 |
| `railTrunkLines` | integer | 3 | 幹線鉄道路線数。現行Enhancementでも最低3を標準とする。 |
| `railStationSpacing` | number | 525 | 駅間隔の基準[m]。 |
| `railInfluenceRadius` | number | 900 | TOD/駅勢圏の計画影響半径[m]。 |
| `railSubCenterSpurs` | boolean | true | 副都心へ支線を生成する。 |

---

## 4. 現行設定

```json
{
  "seed": "random",
  "areaKm2": 100,
  "urbanRatioTarget": 0.4,
  "blockSize": 90,
  "population": 50000,
  "agentCapacity": 60000,
  "vehicleCapacity": 30000,
  "planning": {
    "subCenters": 3,
    "arterialSpacing": 900,
    "collectorSpacing": 360,
    "industrialRatio": 0.08,
    "parkRatio": 0.055,
    "railEnabled": true,
    "railTrunkLines": 3,
    "railStationSpacing": 525,
    "railInfluenceRadius": 900,
    "railSubCenterSpurs": true
  }
}
```

100km²は一辺10km、目標市街地面積は約40km²となる。

人口50,000人 / Agent capacity 60,000 / Vehicle capacity 30,000は大規模都市の試験設定でもある。

---

## 5. Seed運用

### Random

```json
"seed": "random"
```

ブラウザの乱数源から実Seedを生成し、HUD/Consoleへ表示する。

気に入った都市を再生成したい場合は表示されたSeedをJSONへ設定する。

### Fixed

```json
"seed": 123456789
```

同じSeed・都市面積・計画設定で静的都市構造の再現を意図する。

ただしAgentStoreや一部動的処理に `Math.random()` が残っているため、全シミュレーション結果の完全再現は保証しない。

## 6. 鉄道設定の意味

### `railStationSpacing`

駅生成の基準距離。現行525mは旧1050mから短縮された設定で、駅数とTOD重複を増やす。

### `railInfluenceRadius`

駅からの都市開発影響を計算する基準半径。物理的な旅客駅選択距離とは別値。

鉄道旅客の現在の候補駅探索は `RailPassengerIntegration` 側で760m以内を使用する。

### `railTrunkLines`

標準3幹線。各路線は道路回廊型に整列し、共有駅/副都心で乗換可能なネットワークを形成する。

### `railSubCenterSpurs`

trueの場合、副都心へ支線を追加する。支線は必要に応じて実終端駅の車両基地を共有する。

## 7. 起動処理

```text
/config/city.json
  ↓
loadCityConfig()
  ↓
resolveCitySeed()
  ↓
areaKm2 → sizeMeters
  ↓
World / CityPlanning / RailPlanning
  ↓
道路・都市生成
  ↓
人口生成 + 鉄道通勤需要補正
  ↓
Renderer / RailRenderer / UI
```

設定ファイルの取得失敗・値域不正時は起動エラーとして扱う。

---

## 8. 性能上の注意

100km²・5万人・3幹線は負荷試験を兼ねる。

主な負荷:

- Agent更新/Utility AI
- Pedestrian avoidance
- A*
- Traffic edge occupancy
- POI検索
- 3D Instancing/LOD
- 鉄道/駅静的Geometry
- 鉄道旅客状態更新

人口や都市サイズだけでなく、駅間隔を短くすると駅/線路/照明/階段/外装などの静的Instance数も増える。

Performance MonitorでSIMとRenderを分けて確認すること。

---

## 9. 設定追加時のルール

新規設定を追加した場合は:

1. `CityConfigLoader` の型と検証を追加。
2. `public/config/city.json` に標準値を追加。
3. 本書へ型・単位・既定値・意味を追記。
4. `現行仕様書.md` の標準設定表も更新。
