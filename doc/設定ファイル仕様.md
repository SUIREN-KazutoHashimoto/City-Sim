# City-Sim 都市設定ファイル仕様

## 1. 目的

`public/config/city.json` は都市規模、人口、Store容量、都市計画・鉄道計画の**入力値**を定義する。

重要: 本書では「JSONに書かれた生設定」と「コードのmerge/patch後に使われる実効値」を区別する。最終的な正は現行コード。

## 2. 読込経路

```text
/config/city.json
  ↓
CityConfigLoader.loadCityConfig()
  ↓
DEFAULT_CONFIG + raw config
planning = DEFAULT_CITY_PLANNING + raw planning
  ↓
値域検証
  ↓
World / CityGenerator / CityPlanning
  ↓
RailNetworkPlan(options)
```

JSON取得失敗、型/値域不正は起動エラーとして扱う。

## 3. トップレベル

| 項目 | 型 | 現行生値 | 説明 |
|---|---|---:|---|
| `seed` | number / `"random"` | `random` | 都市Seed。randomなら起動時に実Seed生成 |
| `areaKm2` | number | 100 | 都市面積[km²] |
| `urbanRatioTarget` | number | 0.4 | 市街地目標比率 |
| `blockSize` | number | 90 | 基準街区[m] |
| `population` | integer | 50000 | 初期市民要求数 |
| `agentCapacity` | integer | 60000 | AgentStore容量 |
| `vehicleCapacity` | integer | 30000 | VehicleStore容量 |
| `planning` | object | - | 都市/鉄道計画入力 |

`sizeMeters = sqrt(areaKm2 * 1,000,000)`。現行100km²では10,000 m。

## 4. `planning`

| 項目 | 型 | 現行生値 | 説明 |
|---|---|---:|---|
| `subCenters` | integer | 3 | 副都心数 |
| `arterialSpacing` | number | 900 | Arterial基準間隔[m] |
| `collectorSpacing` | number | 360 | Collector基準間隔[m] |
| `industrialRatio` | number | 0.08 | 産業配置計画比率 |
| `parkRatio` | number | 0.055 | 公園配置計画比率 |
| `railEnabled` | boolean | true | 在来鉄道生成 |
| `railTrunkLines` | integer | 3 | 幹線数 |
| `railStationSpacing` | number | 525 | 駅配置基準距離[m] |
| `railInfluenceRadius` | number | 900 | TOD計画影響半径[m] |
| `railSubCenterSpurs` | boolean | true | 副都心支線生成 |

## 5. 現行JSON

```json
{
  "seed": "random",
  "areaKm2": 100,
  "urbanRatioTarget": 0.4,
  "blockSize": 90,
  "population": 50000,
  "agentCapacity": 60000,
  "vehicleCapacity": 30000,
  "planning": {
    "subCenters": 3,
    "arterialSpacing": 900,
    "collectorSpacing": 360,
    "industrialRatio": 0.08,
    "parkRatio": 0.055,
    "railEnabled": true,
    "railTrunkLines": 3,
    "railStationSpacing": 525,
    "railInfluenceRadius": 900,
    "railSubCenterSpurs": true
  }
}
```

## 6. 値域検証

`CityConfigLoader` の現行検証:

| 項目 | 範囲 |
|---|---|
| `areaKm2` | 0.1 .. 10,000 |
| `urbanRatioTarget` | 0.01 .. 0.95 |
| `blockSize` | 20 .. 500 m |
| `population` | 1 .. 1,000,000 |
| `agentCapacity` | population .. 1,500,000 |
| `vehicleCapacity` | 1 .. 1,000,000 |
| `subCenters` | 0 .. 8 |
| `arterialSpacing` | blockSize×3 .. 5000 |
| `collectorSpacing` | blockSize×2 .. arterialSpacing |
| `industrialRatio` | 0 .. 0.35 |
| `parkRatio` | 0 .. 0.25 |
| `railTrunkLines` | 1 .. 3 |
| `railStationSpacing` | 260 .. 3000 m |
| `railInfluenceRadius` | 300 .. 1800 m |

Boolean rail optionsは明示`false`のときだけfalseとして扱う。

## 7. Seed

### Random

```json
"seed": "random"
```

`crypto.getRandomValues()` が利用可能ならUint32 seedを生成する。利用不可時は時刻由来fallback。

### Fixed

```json
"seed": 123456789
```

static city generationの再現を意図する。ただし動的処理の全てが完全決定論ではない。

### Benchmark override

URLの `citysim-seed` はbenchmark sentinelが有効なときだけ受け付ける。通常起動に残ったstale queryは削除して無視する。

## 8. `railStationSpacing` の実効値

現行コード監査上、ここは特に注意する。

`RailPlanningEnhancements.ts` はmodule load時に:

```ts
DEFAULT_RAIL_PLANNING.railStationSpacing *= 1.5;
```

を実行する。しかし通常起動は次の順になる。

```text
DEFAULT_CITY_PLANNING
  ↓
city.json rawPlanning の railStationSpacing=525 で上書き
  ↓
CityPlanning.options
  ↓
RailNetworkPlan(..., options)
  ↓
DEFAULT_RAIL_PLANNING を options=525 で上書き
```

そのため、**現在の通常起動の実効 `railStationSpacing` は525 m**。

「駅間を1.5倍」にする場合、現状コードでは少なくとも次のどちらかが必要になる。

- `city.json` の明示値を787.5へ変更する
- default tuningではなく、config読込後の実効planning valueを1.5倍する設計へ変更する

本書は現在のコード動作を記録するため、意図値787.5ではなく実効525を正として記載する。

## 9. 支線での駅間隔使用

`RailSpurConsistency` は支線の目標spacingを:

```text
max(320, railStationSpacing * 0.90)
```

とする。

通常実効525 mなら支線目標は472.5 m。短すぎる副都心候補では支線を生成せず、nearest trunk stationをSubCenterへ昇格する。

## 10. `railInfluenceRadius`

TOD/都市計画への駅影響半径。旅客の候補駅探索距離とは別値。

`RailPlanningEnhancements` ではshared/SubCenter station等の `influenceRadius` を種類に応じ拡張する場合がある。

## 11. `railTrunkLines`

JSON生値は3。Loaderの許容上限も3。Enhancementはdefaultを最低3へ補正するが、通常設定では最初から3のため実効3。

## 12. 性能への影響

特に負荷へ影響しやすい設定:

- `areaKm2`
- `population`
- `agentCapacity`
- `vehicleCapacity`
- `blockSize`
- `railStationSpacing`

駅間隔を短くするとstation/platform/lighting/access/rail operationの対象数が増える。人口/面積だけでなくrail static/dynamic object数もPerformance Monitorで確認する。

## 13. 設定変更時の更新対象

設定項目またはmerge方式を変更した場合:

1. `CityConfigLoader.ts` の型/検証
2. `public/config/city.json`
3. 本書
4. `現行仕様書.md`
5. 実効値がruntime patchで変わる場合は `詳細設計書.md`

を同時に確認する。
