# City-Sim

TypeScript / three.js / Vite で動作するブラウザ向けリアルタイム都市シミュレーションです。標準構成では100 km²・人口50,000人規模の都市で、市民生活、道路交通、公共交通、産業物流、鉄道、電力を同一のシミュレーション時間上で扱います。

## 現行標準構成

`public/config/city.json` の通常起動設定:

- 都市面積: 100 km²（10 km × 10 km）
- 初期人口: 50,000
- Agent capacity: 120,000
- Vehicle capacity: 30,000
- 市街地目標比率: 40%
- 基準街区: 90 m
- 幹線鉄道: 3路線
- `railStationSpacing`: 525 m（基準値）
- 駅影響半径: 900 m
- 電力: 火力2基、太陽光3基、外部系統2接続

`railStationSpacing=525` は固定駅間隔ではなく、郊外ほど最大約2倍へ広がる基準値です。`planning.parkRatio=0.055` も初期都市計画の入力値であり、最終公園率そのものではありません。

## 主な現行機能

### 都市・建物

- CBD、副都心、用途地区、道路階層、Block / Parcel、建物 / POIの手続き生成
- 密度に応じた多車線道路とLocal道路密度の調整
- 高さ帯別の公園整理、森林、農場、郊外工業・物流拠点
- 駅周辺の線路包絡・建築禁止clearance
- 電力施設を通常の接道済みBuildingとして生成し、建物のPOI・Inspector・LOD・クリック判定へ統合

### 市民・道路交通

- Utility AIによる勤務、食事、買物、娯楽、帰宅
- 徒歩、自家用車、バス、タクシー、鉄道の実移動
- 多車線、車線変更、右左折レーン、信号、横断歩道、IDM系追従
- 歩行者信号待ちと横断中の車両競合制御

### バス・タクシー・物流

- 一般バス路線は実道路走行距離ベースで1路線5 km以下
- バス・タクシー・物流トラックは専用営業所を使用
- 農場 / 原料工場 → 加工工場 → 組立工場 → Retail / Food または外部輸出の物理物流
- 火力発電所向け燃料トラックは市内原料在庫または外部ゲートから実走行で補給

### 職場・ライフライン

- 一般職場は `present / assigned / capacity` を区別
- 生産拠点は出勤率と給電状態を生産効率へ反映
- 発電所は3交代のライフライン職場として扱い、在籍人数の30%を同時勤務目標とする
- ライフラインは「現在建物内にいる人数」ではなく、そのシフトに実際にチェックインした `onDuty` 人数を運転能力へ使用
- シフト交代45分、起動直後60分のgraceを持つ

### 電力

- 火力、太陽光、外部受電、変電所、地下電力網、需要家、優先給電、非常電源
- 50 Hz / 22 kV系統の近似電力品質モデル
- 発電能力へ人員充足と燃料在庫を反映
- 電線・電柱は地下埋設扱いで通常描画しない
- 発電所、変電所、外部受電所は通常Buildingとして地上描画
- 線路・変電所の定格は現在は即時遮断値ではなく過負荷診断値として扱い、接続障害と供給源容量をhard constraintとする

### 鉄道・描画

- 在来鉄道3幹線、副都心支線、普通 / 快速 / 特急、閉塞・信号、15秒グリッドダイヤ
- 終端駅、車両基地、回送、実列車への乗降、駅内3D移動、最大1回乗換
- 外部接続高速鉄道
- GPU Instancing、距離LOD、SharedArrayBuffer / Worker、A* cacheによる大規模化対応

### UI / 診断

- `F10` 全画面メニュー
- 建物、乗用車、バス、タクシー、トラック、列車、電力、グラフィックスの一覧 / 診断
- 建物用途、車両状態、バス・タクシー・トラック・列車状態のグラフ
- 電力需給の時系列グラフと、市内発電余力 / 外部受電余力の分離表示
- 一覧から対象Building / Vehicle / Trainへジャンプ
- Inspector、Dashboard、Performance Monitor、描画filter

都市診断オーバーレイは未実装で、交通・電力を起点とする共通Overlay基盤として [`ROADMAP.md`](ROADMAP.md) で計画しています。

## 開発

```bash
npm install
npm run dev
```

ビルド:

```bash
npm run build
```

CI相当の確認では `npm ci`、`npm run build`、`npm run bench:power` を使用します。配布物には `LICENSE`、`NOTICE`、`THIRD_PARTY_NOTICES.txt` を保持してください。

ブランチ・PR・version運用は [`doc/開発・不具合修正手順.md`](doc/開発・不具合修正手順.md) を参照してください。`develop` は保護されており、通常の変更はPRと必須`build` checkを経由して統合します。
